# FreeNet 0.8 — устойчивый автоматический выбор VPN

## Цель

AUTO VPN сохраняет работающее подключение, пока нет достаточных свежих данных для улучшения. Разовый скачок задержки, незавершённый замер скорости или недоступность одного сайта не должны превращаться в случайное переключение. Проверка доступности VPN, улучшение качества и аварийное восстановление имеют отдельные условия допуска.

## Подтверждение ухудшения

При доступном HTTPS и четырёх доступных сервисах задержка ниже 300 мс считается нормальной. Для задержки сохраняется существующий гистерезис: 300–419 мс дают один балл, 420–649 мс — два, от 650 мс — три. Для сравнения нужны минимум четыре балла и два последовательных наблюдения в пределах двадцати минут. Один высокий скачок не запускает поиск.

Для частичной недоступности сервисов действует отдельное подтверждение:

- Используются четыре существующие проверки Instagram, Telegram Web, WhatsApp Web и YouTube. Новых внешних проверок и дополнительных пользовательских настроек нет.
- Нужны не менее четырёх завершённых наблюдений в течение двадцати минут; от первого до последнего должно пройти минимум две минуты. Хотя бы один и тот же сервис должен оставаться недоступным на протяжении всей последовательности.
- Успех всех четырёх сервисов, незавершённая проверка, смена текущего подключения или отсутствие общего проблемного сервиса прерывают последовательность. Ошибка запуска проверочного процесса и неизвестный результат не считаются подтверждением проблемы.
- Сервисный сигнал разрешает только сравнение качества. Он не считается доказательством полного отказа VPN и не запускает аварийную ветку.

Оба сигнала используют общую сохранённую паузу между поисками. Для сервисного сигнала она составляет один час; для задержки сохраняются один час и существующее сокращение до пятнадцати минут при выраженной деградации. Одновременные сигналы создают один поиск. Если паузу нельзя надёжно прочитать или сохранить, затратный поиск не запускается.

## Выбор и повторная проверка

1. Сначала выполняется полный свежий замер текущего VPN. Нужны доступность, достаточные HTTPS-измерения и минимум три завершённых потока измерения скорости. Отсутствующий результат не считается плохой скоростью. Если текущий VPN уже удовлетворяет критериям качества, поиск замены прекращается.
2. Для сравнения сохраняются существующие требования к кандидатам: скорость, задержка HTTPS, разброс задержки, стабильность потоков и доступность сервисов. Сохранённая для показа пользователю скорость не подменяет свежие измерения.
3. Поиск улучшения не обновляет endpoint текущего профиля до сравнения. Выбирается точный кандидат из измеренного снимка; случайный endpoint из повторно загруженной подписки не подставляется.
4. Перед применением кандидат ещё раз проходит короткую проверку HTTPS и всех четырёх сервисов. Затем повторно проверяется текущий VPN: исходная проблема должна всё ещё подтверждаться. Такой порядок позволяет отменить переключение, если общая временная проблема уже исчезла.
5. Непосредственно перед запуском изменения повторно проверяются срок операции, текущий профиль, свежесть снимка, настройки AUTO, разрешённая география и защитные блокировки. Восстановление текущего VPN, отмена, неизвестный результат или устаревшие данные оставляют подключение на месте.

Повторное подтверждение ограничено по времени и не повторяет измерение скорости. Обычный ручной выбор и аварийное восстановление сохраняют свои существующие правила. Защита от ненужного переключения здорового сервера, единичное выполнение операции, транзакционное применение, проверка результата и rollback остаются в силе. Неизвестный результат rollback запрещает дальнейшие автоматические изменения до установления фактического состояния.

## Сохранение состояния

Счётчики подтверждения и пауза хранятся в существующем файле состояния. Обновления из фонового процесса и приложения выполняют чтение, изменение и атомарную замену под общей ограниченной по времени файловой блокировкой. Это не позволяет обычному обновлению статуса здоровья затереть сохранённую паузу подбора.

## Проверка

Регрессионные проверки охватывают незавершённые измерения, смену проблемного сервиса, минимальную продолжительность наблюдений, неизвестные результаты, смену профиля, общую паузу и ошибки сохранения. Отдельно проверяются повторная проверка выбранного кандидата, восстановление текущего VPN во время поиска, отмена, устаревший снимок и изменение настроек перед применением.

Проверки и сборки выполняются в GitHub Actions для точного состава изменений. После официальной установки проверяются версия, текущий VPN, числовая скорость и отсутствие незавершённой транзакции. Успешная установка и здоровый статус сами по себе не доказывают прохождение реального аварийного переключения; для этого нужен соответствующий наблюдавшийся инцидент.
