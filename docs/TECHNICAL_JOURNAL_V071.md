# FreeNet v0.7.1 — разделённый Журнал и технический лог

Основа: v0.7.0, ветка `stable/v0.7`. Логика AUTO VPN, алгоритмы проверки/переключения, Xray, DNS, маршрутизация, установщик и обновление не изменяются.

## Две независимые аудитории

**Журнал** (`/api/journal`, интерфейс «Журнал»): только значимые события,
короткая понятная формулировка, наглядный результат, раскрываемые полные подробности,
отдельные фильтры и CSV. Существующие правила агрегации штатных проверок
сохраняются. Никаких сетевых действий при просмотре.

**Технический лог** (`/opt/var/log/freenet-technical.jsonl`): отдельный JSONL-архив,
только этапы инцидентов, блокировок, откатов, замены, ошибок,
ручных действий, обновлений и решений автоматики.
Каждая запись содержит UTC-время события и UTC-время наблюдения, источник,
категорию, этап, исход, уровень, обезличенное сообщение, ID инцидента (если есть)
и краткий срез уже имеющегося состояния AUTO/health/rollback/quality.

Данные отправляются в ограниченную асинхронную очередь на запись **после**
завершения первоначальной записи обычного журнала и **после** освобождения его
блокировки. Переполнение очереди и ошибки технической записи не меняют логику
и результат AUTO VPN. Число пропусков/ошибок считывается только через экспорт.

## Ротация и нагрузка

- Технический файл: до 2 МиБ; одна архивная ротация `.1` (суммарно около 4 МиБ).
- Очередь: 128 событий, переполнение не блокирует автоматику.
- Идентичные неаварийные сообщения: подавление повторов на 2 минуты.
- Этапы с `incident=` и rollback не агрегируются.
- Нет добавленных health-check, TCP/HTTPS/DNS-запросов, фонового опроса VPN,
  проверки внешнего IP или изменения state/config.
- Архив остаётся дополнением к существующим исходным журналам, не заменяет их.

## Полный диагностический экспорт

В интерфейсе «Журнал» → **Скачать технический лог**,
либо авторизованный GET `/api/journal/diagnostics`.

JSON содержит:

1. Версию, UTC-момент формирования, модель отчёта и замечание о read-only режиме.
2. До 2000 исходных строк истории AUTO VPN и до 2000 исходных строк системного
   журнала **без** обычной UI-агрегации (глубина ограничена сохранённой историей).
3. До 1200 уже записанных технических событий с этапами инцидентов и
   краткими состояниями. Архивная часть файла тоже читается.
4. Состояния AUTO VPN, health watchdog, результатов, блокировки мутаций,
   защиты после обновления, rollback, счётчиков деградации и времени оптимизации.
5. Сведения о завершившемся self-update, без секретов.
6. Linux/Go архитектуру, uptime, свободную память, метаданные наличия,
   длины и времени изменения файлов; для небольшой конфигурации — только
   ограниченный SHA-256-отпечаток, **без** содержимого.

Обращение к endpoint работает только на **скачивание**: не инициирует тестов
сети и не влияет на текущий VPN.

## Безопасность

- API проходит штатную аутентификацию FreeNet.
- Исходные URL, адреса серверов, IP, UUID, bearer-токены и известные поля
  credential редактируются перед сохранением и перед экспортом.
- Пароли, конфигурации Xray, ключи и подписки в отчёт не включаются.
- Полная автоматическая проверка возможных секретов свободного текста
  не гарантируется: перед передачей файла третьим лицам его следует
  считать диагностическими данными и при необходимости проверить.

## Как собирать данные с трёх роутеров

1. После штатной runtime-проверки **HOME** установить диагностическую версию.
2. На каждом разрешённом к обновлению роутере открыть «Журнал» → «Скачать
   технический лог». Сохранить файл с префиксом **HOME**, **WORK**, **MOM**.
3. Скачивать независимо с каждого устройства. Один и тот же формат
   позволяет сравнивать время, цепочки инцидентов и изменения конфигурации.
4. Для расследования отправить три JSON-файла и кратко указать,
   на каком устройстве и когда наблюдалась проблема.

**CI не равен runtime-проверке VPN.**
Первый полноценный эксплуатационный тест — только HOME.
Обновление WORK/MOM требует отдельного подтверждения после runtime HOME.
