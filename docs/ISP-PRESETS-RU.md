# Профили интернет-провайдеров FreeNet Router

## Назначение

FreeNet хранит несекретные сетевые метаданные по отдельным профилям интернет-провайдеров. Профиль не привязан к адресу, дому, офису или другому названию площадки.

Источник несекретных метаданных: `config/isp-presets.json`.

## Текущая продуктовая модель

ISP profile **не создаёт routing policy автоматически**. FreeNet не должен делать выводы вида «если выбран провайдер X, то YouTube/сервис Y нужно отправить DIRECT/VPN/BLOCK».

Routing задаётся только одним из безопасных способов:

1. явное пользовательское правило в «Маршрутизации»;
2. подтверждённый runtime-факт, оформленный отдельным продуктовым изменением и покрытый acceptance;
3. ручной экспертный `custom` policy.

До такого подтверждения все ISP routing presets остаются `explicit-only`: metadata/read-only, `MUTATION: NONE`, без автогенерации правил.

## Профили

- `auto` — определить безопасный вариант без безусловного изменения работающей конфигурации;
- `vladlink` — Владлинк;
- `alliancetelecom` — АльянсТелеком;
- `rostelecom` — Ростелеком;
- `podryad` — Подряд;
- `custom` — ручной экспертный профиль.

Каждый ISP ID самостоятельный. Изменение одного профиля не должно автоматически менять другой.

## Routing policy

Старый baseline `ISP → YouTube DIRECT/VPN` удалён из product model. Ни Владлинк, ни АльянсТелеком, ни Ростелеком, ни Подряд не получают автоматическое YouTube-правило только по факту выбора ISP.

Отдельные сервисные правила, например Bosch или YouTube, добавляются только после подтверждённого факта или явного ручного правила. Если такого факта нет в текущей конфигурации/задаче, сервис нельзя считать product baseline.

## ISP и DNS — разные настройки

В Browser Setup и Control Center пользователь отдельно выбирает:

1. интернет-провайдера;
2. режим DNS;
3. routing policy, если она действительно нужна.

Выбор провайдера сам по себе не должен переписывать VPN credentials, Xray routing или DNS/routing-конфигурацию. До применения FreeNet показывает текущее состояние, ожидаемые изменения и то, что останется неизменным.

## DNS

FreeNet не предполагает одинаковую DNS-топологию у всех операторов. Для каждого ISP профиль DNS проходит собственный runtime acceptance.

Безопасный принцип:

- уже рабочую DNS-схему сохранять, если её замена не требуется;
- Split DNS через XKeen/Xray включать только явно;
- не создавать второй listener `:53`, если порт уже корректно обслуживается штатным DNS роутера;
- не менять VLESS credentials и non-DNS routing в рамках DNS apply.

## Безопасное применение

Любая операция, которая действительно меняет DNS или routing, выполняется последовательно:

1. факты текущего состояния;
2. точный ожидаемый delta;
3. backup;
4. candidate-конфигурация;
5. `xray run -test` до live apply;
6. атомарное применение;
7. runtime acceptance;
8. rollback при ошибке после mutation.

Основная ошибка и результат отката фиксируются раздельно.

## Безопасность данных

ISP/DNS preset — несекретная настройка. Subscription URL, UUID, Reality keys, shortId, пароли и credential-bearing конфиги в этот слой не входят и не публикуются в GitHub/API/logs.
