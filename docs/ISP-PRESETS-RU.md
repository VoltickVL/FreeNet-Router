# Профили интернет-провайдеров FreeNet Router

## Назначение

FreeNet хранит поведение сети по отдельным профилям интернет-провайдеров. Профиль не привязан к адресу, дому, офису или другому названию площадки: один и тот же оператор должен получать одинаковую базовую политику на любом совместимом роутере.

Источник несекретных метаданных: `config/isp-presets.json`.

## Профили

- `auto` — определить безопасный вариант без безусловного изменения работающей конфигурации;
- `vladlink` — Владлинк;
- `alliancetelecom` — АльянсТелеком;
- `rostelecom` — Ростелеком;
- `podryad` — Подряд;
- `custom` — ручной экспертный профиль.

Каждый ISP ID самостоятельный. Даже если два оператора сейчас используют одинаковую политику, изменение одного профиля не должно автоматически менять другой.

## Подтверждённая базовая маршрутизация

### Владлинк

- YouTube: `DIRECT`;
- остальные сервисные исключения добавляются только отдельным подтверждённым правилом.

### АльянсТелеком

- YouTube: `DIRECT`;
- профиль отдельный от Владлинка, несмотря на одинаковое текущее правило YouTube.

### Ростелеком

- YouTube: `VPN`;
- остальные сервисы не отправляются через VPN автоматически только потому, что выбран Ростелеком.

### Подряд

Маршрутизация не считается подтверждённой. FreeNet не должен автоматически наследовать поведение Ростелекома, Владлинка или АльянсТелеком до отдельного runtime acceptance.

### Отдельные сервисы

Правила для отдельных сервисов, например Bosch, не входят в базовый профиль без подтверждённого факта. На текущем состоянии репозитория отдельное Bosch-правило не найдено, поэтому его нельзя считать product baseline.

## ISP и DNS — разные настройки

В Browser Setup и Control Center пользователь отдельно выбирает:

1. интернет-провайдера;
2. режим DNS.

Выбор провайдера сам по себе не должен переписывать VPN credentials или Xray-конфигурацию. До применения FreeNet показывает текущее состояние, ожидаемые изменения и то, что останется неизменным.

## DNS

FreeNet не предполагает одинаковую DNS-топологию у всех операторов. Для каждого ISP профиль DNS проходит собственный runtime acceptance.

Безопасный принцип:

- уже рабочую DNS-схему сохранять, если её замена не требуется;
- Split DNS через XKeen/Xray включать только явно;
- не создавать второй listener `:53`, если порт уже корректно обслуживается штатным DNS роутера;
- не менять VLESS credentials и non-DNS routing в рамках DNS apply.

## Безопасное применение

Любая операция, которая действительно меняет DNS или routing, выполняется последовательно:

1. факты текущего состояния;
2. точный ожидаемый delta;
3. backup;
4. candidate-конфигурация;
5. `xray run -test` до live apply;
6. атомарное применение;
7. runtime acceptance;
8. rollback при ошибке после mutation.

Основная ошибка и результат отката фиксируются раздельно.

## Безопасность данных

ISP/DNS preset — несекретная настройка. Subscription URL, UUID, Reality keys, shortId, пароли и credential-bearing конфиги в этот слой не входят и не публикуются в GitHub/API/logs.
