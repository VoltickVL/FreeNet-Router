# Аудит AutoVPN: устойчивый видео-трафик и предсказуемая нагрузка

Дата: 29.10.2026. Основание: аппаратная приёмка Portable FreeNet beta.49, [#1225](https://github.com/VoltickVL/FreeNet-Router/issues/1225), [#7](https://github.com/VoltickVL/FreeNet-Router/issues/7). Контекст: Xray v26.10.21, XKeen 2.1; отдельный VPN на MagicBook-Pro не является источником замеров FreeNet.

## Продуктовый контракт

**Цель:** пока VPN исправен — не трогать; если повторно подтверждена медленная передача — самостоятельно сравнить разрешённые VPN и применить проверенный лучший; подтвердить результат, при неуспехе восстановить рабочее состояние. Пользователь не должен пользоваться SSH, запускать тесты или вручную выбирать страну.

- Рабочий маршрут: *лёгкая проверка доступности → периодическая последовательная медиа-проба → два независимых плохих наблюдения → ограниченное сравнение кандидатов → повторная проверка текущего и выбранного → применение → проверка результата / откат*.
- Не менять DNS/ISP/routing presets, существующие XKeen/Xray и credentials из-за деградации видео.
- Любой точный `rollback=FAILED/UNKNOWN`, незавершённый checkpoint, изменившаяся идентичность текущего VPN — STOP. Нельзя спутать отказ до mutation с неизвестным откатом.
- Исход `busy` означает *подбор не выполнен*, а не *все серверы плохие*. Нельзя расходовать cooldown за не начатый scan.
- Не объявлять HTTP 403/429 от ChatGPT или Instagram доказательством отказа VPN. Суррогатные HTTPS-сегменты не являются воспроизведением Reels.

## Установленные аппаратные факты

На beta.49 (28.10.2026) `/versionz=beta.49`, `/healthz=ok`, updater `SUCCESS / NOT_NEEDED`; transaction doctor `NO_CHECKPOINT`, `mutation_blocked=false`; AutoVPN `enabled/best/degraded/auto_apply`. После обновления watchdog измерял контрольные медиа-сегменты **0,6–3,5 Мбит/с** и фиксировал `uncertain`. В 15:02:43Z `quality_optimization:start` → `quality_optimization:busy` («другая AUTO VPN операция уже выполняется»); фактически не завершено сравнение. Последний доказанный `switched` — 27.10.2026 21:13:21Z. GID mismatch из native Xray inventory остаётся отдельной диагностикой #1227, а не доказательством неполадки provider apply. Работа на реальном роутере во время аудита была только read-only.

## Выявленные проблемы

1. **Зависшая блокировка Best scan:** `/tmp/freenet-auto-best.lock` хранит PID и задерживает повторный подбор до 15 минут после рестарта FreeNet. Исправление: проверка владельца через `/proc`, безопасный reclaim при подтверждённом отсутствии процесса, защита живого владельца и старый TTL для неизвестного владельца.
2. **BUSY съедает retry:** `QUALITY_OPTIMIZATION_LAST` резервируется до захвата Best/health lock. Даже несостоявшаяся попытка занимала 10-минутную паузу. Исправление: возврат ровно своей reservation при `busy`, с compare-and-swap по timestamp. Реальный завершённый scan сохраняет cooldown.
3. **Слишком дорогой watchdog:** при интервале 30 секунд 2 × 512 КиБ = до 2,88 ГиБ/сутки только на медиа-загрузки, плюс множество HTTPS-проверок и отдельный Xray. Исправление: лёгкие проверки по настроенному интервалу; **две последовательные 256-КиБ загрузки не чаще одного раза за 90 секунд**. Теоретический максимум регулярного media-трафика ≈ 480 МиБ/сутки (экономия ≈83%), без учёта RTT/HTTP заголовков и глубокой диагностики. При полном подборе дополнительные нагрузочные проверки ограничены количеством кандидатов и дедлайном; регулярный watchdog не запускает конкурирующую нагрузочную проверку во время работающего Best scan.
4. **Непрозрачный отказ кандидатов:** журнал «нет подходящих» не показывает, сколько профилей реально проверено. Исправление: компактная сводка *разрешено / полно измерено / медленно / не завершено / Eligible / урезано бюджетом*. Никаких subscription URL, UUID, ключей или полных конфигов в журнале.
5. **Видео и сервисы измерялись раздельно:** при media-only подборе главным критерием были завершённые сегменты и общий application RTT, а Instagram/ChatGPT не отражались в ранжировании. Исправление: **только после успешной последовательной загрузки** ограниченные HTTPS-сигналы сервисов + ChatGPT; подтверждённый service transport failure мягко ухудшает оценку, неизвестный/антибот HTTP не исключает сервер. Полная проверка до изменения конфигурации сохранена.

## Оставшиеся осознанные границы

- Для допуска к AUTO media выбранный сервер должен **сам** успешно пройти две последовательные загрузки, порог 8 Мбит/с, ограничение задержек/джиттера и повторный pre-apply admission. Не подменяем это высоким агрегатным Speedtest. Не снижаем пороги без реального распределения причин отклонения — иначе AutoVPN может начать менять один медленный сервер на другой.
- RTT-shortlist допускает до 64 профилей с не более чем двумя параллельными изолированными пробами, а глубокий отбор ограничен коротким списком и дедлайном. Это эпизодическая нагрузка, **не постоянный фоновый benchmark**.
- Доступность chatgpt.com/instagram.com по публичному HTTPS — только косвенный сигнал. Нельзя гарантировать работу приложения, доступ к аккаунту, streaming CDN, QUIC, IPv6 или видео на конкретном устройстве по одному тестовому URL.
- `routing-gid-mismatch` требует отдельной проверки native core update; не проводить restart/kill ради AutoVPN и не отменять процессную защиту.

## Приёмка релиза

**CI:** тесты живого/мертвого владельца Best lock, паузы и ресурса фоновой медиапробы, сохранения полноценной pre-apply проверки, возврата cooldown при BUSY, измерения/агрегирования медиаданных, мягких сигналов ChatGPT/Instagram, регрессии rollback и updater. PR CI и release CI только с terminal SUCCESS.

**Runtime Portable:** версия → updater terminal SUCCESS → `NO_CHECKPOINT`, `mutation_blocked=false` → bounded watchdog → `quality_optimization` с измеренными причинами исключения → `switched` на реально другой VPN → подтверждённый post-apply QoE / rollback. Если реального кандидата нет, фиксировать фактические критерии его исключения; без новой terminal switch acceptance не закрывать #1225.

## Не делать

Не использовать клиентский VPN MagicBook для атрибуции, не снижать сразу все пороги, не устраивать частые ручные Speedtest, не ослаблять rollback, не добавлять raw terminal в Control Center и не требовать SSH от Management.
