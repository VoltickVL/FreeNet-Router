# FreeNet 0.8 — выпуск и безопасное разделение каналов

## Каналы

**Stable** — только `vMAJOR.MINOR.PATCH`, GitHub Release без признака prerelease. Это штатный `releases/latest`, браузерный catalog по умолчанию и установщик без дополнительных флагов. Beta не должна попадать в Stable по названию, кэшу или fallback.

**Beta** — только `vMAJOR.MINOR.PATCH-beta.N`, N=1..99 и `prerelease=true`. Публикуется через `beta/v0.8.0` и не становится GitHub `latest`. На Stable-пользователе канал Beta может быть открыт только вручную в менеджере версий. На Beta-пользователе автоматической замены Stable/новыми Beta нет: требуется выбор exact target и подтверждение.

Каталог `GET /api/system/update/releases` возвращает Stable. Запрос `?channel=beta` отдельно возвращает только опубликованные Beta (черновики и неправильно размеченные теги не допускаются). В случае отказа Beta-каталога нельзя подставлять Stable fallback как будто он Beta.

## Контур обновления

1. Пользователь явно открывает Beta в менеджере версий, выбирает конкретную версию, видит предупреждение.
2. `GET /api/system/update/plan?target=<exact-beta>&channel=beta` — только read-only plan, проверка опубликованного prerelease, точного тега и SHA-256, проверка архитектуры. Никакого изменения Xray/VPN/DNS.
3. Отдельное подтверждение установки Beta. Backend проверяет `beta_acknowledged`, same-origin, права сессии, блокировку UNKNOWN rollback и строгое имя тега.
4. POSIX updater **независимо** требует `FREENET_UPDATE_BETA_OPT_IN=yes` для prerelease; метаданные `prerelease` и exact tag обязаны соответствовать друг другу. Stage → snapshot → install FreeNet-only → acceptance → restore/STOP при ошибке.
5. Stable доступен в отдельном канале. Для возврата с Beta требуется выбор конкретного стабильного релиза и такой же план/подтверждение; локальные секреты не передаются в GitHub.
6. Новый пилотный установщик поддерживает только `FREENET_INSTALL_RELEASE_TAG` + `FREENET_INSTALL_BETA=yes` для явного Beta. Без них неизменно устанавливается Stable, без скрытого перенаправления на prerelease. Старый установщик 0.7.4 не предполагается изменённым задним числом.

## Правило релиза

- Основная ветка разработки `dev/v0.8`, изменения в неё только после terminal CI и ревью точного HEAD.
- Beta release cut выполняется из **новой** `beta/v0.8.0`, созданной от подтверждённого `dev/v0.8`; исходная устаревшая `beta/v0.8` не переписывается и не используется. В отдельном коммите меняется только `VERSION` на `v0.8.0-beta.N`.
- Workflow публикует `gh release create --prerelease --latest=false` после тестов, сборки трёх бинарников, manifest и проверки обязательных русских заметок. Ветка `stable/v0.7` сохраняет прежнее стабильное поведение.
- Публикация сборки не означает hardware PASS и не запускает принудительное обновление HOME/WORK/MOM. Для выхода в Stable требуются реальные runtime-facts: безопасное ручное переключение/rollback, AUTO continuity, VPN-required HTTPS через LAN и сохранение исправного Xray.

## Регрессионная матрица

Stable каталог не содержит Beta. Beta каталог не содержит Stable. Плохой тег, неправильный флаг `prerelease`, draft, отсутствие opt-in, повреждённый SHA-256 и чужой target — STOP без запуска установки. Семантика версии: `v0.8.0-beta.2 > v0.8.0-beta.1`, но `v0.8.0 > v0.8.0-beta.99`, при этом `v0.8.0-beta.1 > v0.7.14`. Никакого автоматического перехода между каналами, когда пользователь лишь смотрит раздел.
