# FreeNet Router v0.8.0-beta.79

## Что изменилось

### Дополнительный факт для диагностики Reels и Telegram: TCP/UDP 443

В разделе **Control Center → Настройки → Видео и связь — диагностика** расширен read-only снимок: теперь показывается, присутствуют ли в текущей таблице kernel conntrack соединения **TCP/443**, **UDP/443**, оба типа или ни одного для устройства, открывшего панель непосредственно по локальной сети.

- Снимок читается по нажатию кнопки «Снять диагностическое состояние», не открывает новых соединений, не перезапускает процессы, не меняет правила маршрутизации, DNS, XKeen/Xray или VPN.
- Используются только сведения из `/proc/net/nf_conntrack` или старого `/proc/net/ip_conntrack`, чтение ограничено 256 КиБ. Нет доступа к сырым журналам, спискам клиентов и сетевым секретам. В API наружу передаётся **только одно из пяти фиксированных значений**, без IP, портов источника, MAC, имён доменов и адресов назначения.
- Если невозможно достоверно определить прямой локальный IPv4 socket peer, данные отсутствуют, снимок обрезан или возникла ошибка — **UNKNOWN**, а не ложный успех. `Forwarded`, `X-Forwarded-For` и другие заголовки подмены клиента не используются.
- Важное ограничение: **наличие UDP/443 не доказывает QUIC**, наличие TCP/443 не доказывает Instagram/Telegram, а отсутствие записи не означает отсутствие реального видео. Маршрут VPN/DIRECT, DNS/CDN, клиентский QUIC и playback по-прежнему UNKNOWN до независимой фактической проверки.

## Исходная проблема и текущий результат

Management сообщает: Instagram Reels и видео Telegram могут буферизовать при маршрутизации через FreeNet, но при отдельном VPN-приложении на том же устройстве воспроизводятся плавно. **В beta.79 это не исправлено.** Расширена пассивная диагностика для дальнейшего поиска PRIMARY ERROR: клиентский HTTPS egress, DNS/CDN, сетевой протокол, стабильность передачи сегментов и отличие маршрута от standalone VPN.

Отдельно: **Split DNS не объявлен обязательным**, смена MTU, VPN-страны и покупка Netcraze Ultra без доказательства первопричины не предлагаются.

## Что дальше

Публикация beta.79 **не означает её установку на реальном роутере**. Нельзя объявлять устранение тормозов без проверки фактического клиентского видео и сопоставления с отдельным VPN-приложением. Дальнейшая аппаратная приёмка возможна только через штатный FreeNet safe plan, terminal update/rollback receipt и read-only диагностику без скрытых сетевых изменений. MOM сохранять как эксплуатационное окружение, Portable с `FAILED_UNKNOWN` — STOP до reconciliation.
