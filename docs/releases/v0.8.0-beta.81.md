# FreeNet Router v0.8.0-beta.81

## Что изменилось

### Управляемое испытание альтернативного QUIC flow для текущего VPN

В **Control Center → Настройки → AUTO VPN** добавлены две отдельные команды: «Проверить совместимость QUIC» (без изменения сети) и «Испытать с автоматическим откатом». Применяется только к единственному подтверждённому VLESS Reality TCP/RAW outbound с `xtls-rprx-vision`: временно переключает клиентский flow в `xtls-rprx-vision-udp443` на том же сервере, с теми же credentials, DNS, ISP и Routing. Это опциональное ручное испытание, **не** автоматическое изменение всех роутеров.

Перед испытанием FreeNet проверяет точный состав и идентичность действующего outbound, отсутствие чужих операций и обновления, проводит `xray run -test -confdir` на приватной полной копии конфигурации, выдаёт ограниченный по времени plan token и создаёт долговечный приватный checkpoint до изменения активного файла. Изменение блокируется при неизвестном runtime, несовпадении исходной конфигурации, занятом writer lock или неудачной проверке. При успешном запуске режим действует 35 секунд, после чего исходный конфиг восстанавливается с контролируемым restart. Предусмотрено восстановление при следующем старте FreeNet, если испытание прервалось. Неподтверждённый rollback = STOP последующих VPN mutation.

**Важно:** оба режима могут по-разному обрабатывать UDP/443/QUIC. Тест совместимости и даже успешный короткий canary **не подтверждают** плавное воспроизведение Reels или устранение intermittent buffering; это отдельная аппаратная приёмка. На время самого испытания возможен разрыв активных соединений, поскольку используется restart XKeen/Xray. Не запускать тест на работающем соединении без необходимости, не применять на MOM/Portable или одновременно на нескольких устройствах.

## Что остаётся открытым

Редактирование `ip_exclude.lst`, `port_exclude.lst`, `port_proxying.lst` через FreeNet ещё отсутствует и относится к **отдельному следующему scoped PR**. Отдельные задачи — исключение необоснованного обхода портов, анализ full-device capture, прикладной QoE/AutoVPN failover без перезапусков. Не объявлять Stable и не утверждать, что проблема Reels решена без client-path acceptance.

## Приёмка

Release CI, SHA256SUMS и полный комплект артефактов проверяются после публикации. Установка Beta на роутеры, runtime-rollback и пользовательский Reels playback подтверждаются отдельно; публикация в GitHub их не доказывает.
