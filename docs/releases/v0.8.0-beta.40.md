# FreeNet v0.8.0-beta.40

## Что изменилось

### Каталог версий Xray теперь доступен через резервный проверенный VPN-путь

На роутере с действующим Xray и FreeNet beta.39 окно «Версия Xray Core» могло показывать `Xray release catalog is unavailable`, потому что запрос каталога выполнялся только по прямому HTTPS-маршруту `SO_MARK=255` к GitHub API. Резервный VPN-путь beta.39 использовался лишь позднее для ZIP-архива, поэтому до стадии выбора версии обновление не доходило.

- Сначала FreeNet пытается получить каталог с официального GitHub API напрямую, с ограничением по времени.
- Только при подтверждённой транспортной ошибке, тайм-ауте или HTTP 403/429/451/5xx выполняется **один** резервный запрос к тому же официальному API через временный изолированный Xray и локальный SOCKS5 с фактическим текущим VPN-outbound.
- Временный Xray использует защищённый каталог, marker диагностического процесса и существующую блокировку probe; после запроса завершается. **Рабочий Xray, XKeen, VPN, DNS, маршруты и credentials не меняются.**
- HTTP 404/401, неверный формат, избыточный размер каталога, недоверенный asset, отмена запроса либо неопределённый активный outbound → безопасная остановка без попыток обновления ядра.
- Сохраняется требование официального GitHub digest/SHA-256 до загрузки и установки ZIP, а также snapshot/controlled restart/rollback. Ошибки DIRECT и резервного запроса возвращаются конечными кодами, без URL и секретов.

### Проверки

Добавлены тесты приоритета DIRECT, единственного резервного запроса, отмены, HTTP-кодов, размера и неизменности официального каталога. Существующие тесты валидации каталога, архива, восстановления и отложенного обновления выполняются в обязательном CI.

## Ограничения

**Не исправляет другую подтверждённую проблему переключения VPN**: `safe core-only Xray restart preflight failed; reason=multiple-xray-processes`. Это отдельная существующая задача [#1227](https://github.com/VoltickVL/FreeNet-Router/issues/1227). Нельзя обходить проверку количества процессов ради переключения сервера; требуется read-only классификация действительного процесса и диагностических дочерних Xray до отдельного контролируемого исправления.

После выпуска необходима штатная аппаратная проверка доступности каталога на роутере у мамы. Установка нового Xray разрешена только после успешного плана и подтверждённого состояния runtime.
