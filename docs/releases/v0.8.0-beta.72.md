# FreeNet Router v0.8.0-beta.72

## Что изменилось

### Безопасный Refresh текущего VPN и точная диагностика VLESS/Reality

На WORK, HOME и MOM в beta.71 штатный read-only VPN doctor одинаково обнаружил `active_outbound_stale_or_mismatched`: среди 50 профилей найден текущий сервер, TCP и изолированный HTTPS через новый профиль успешны, но действующий Xray outbound отличается от версии в подписке. На WORK отдельно подтверждены названия отличающихся полей Reality: `serverName` и `shortId`. Значения ключей, UUID и секреты не публиковались. При этом рабочий VPN у Management функционирует хорошо, поэтому автоматическая смена сервера не выполнялась.

[PR #1309](https://github.com/VoltickVL/FreeNet-Router/pull/1309) объединяет взаимосвязанные исправления одного механизма:

- Read-only `/api/vpn/runtime-doctor` возвращает `catalog_fresh`, `catalog_source` и **только имена** несовпадающих полей `changed_fields`, без адресов, UUID, ключей Reality или других секретных значений. Защищённый локальный кэш не выдаётся за свежую подписку.
- Для текущего Refresh источник кандидата должен быть **действительно свежим** — direct HTTPS либо HTTPS через уже активный VPN. Protected LKG допустим для диагностики, но при недоступности свежей подписки Refresh останавливается как `NOT_APPLIED`, не подменяя параметры сервера из старого кэша.
- После managed `apply-core` и обязательных сетевых проверок FreeNet подтверждает **точную идентичность всего применённого VLESS outbound**: адрес/порт, UUID, flow, network/security, Reality SNI/shortId/параметры, а также TLS и WebSocket Host/Path. Одного совпадения названия/endpoint и наличия процесса Xray недостаточно. При неясности после изменения — `UNKNOWN/STOP`, никакого скрытого повторного применения.
- Добавлены отрицательные тесты изменившегося Reality SNI/shortId при неизменном endpoint, TLS/WS-параметров, stale кэша, непрочитанной конфигурации и невозможности вывести секреты. Обновлён существующий контрактный тест свежести каталога. GitHub Router и Browser CI подтверждены до merge.

### Что оставлено без изменений

- VPN серверы, работающие на роутерах, автоматически не переключаются одним обновлением FreeNet; применение нового профиля требует штатного guarded Refresh.
- Не меняются DNS, ISP presets, XKeen/Xray binary и GID, настройки маршрутизации, AutoVPN ранжирование и правила UDP/STUN/WebRTC.
- Для устройств класса 512 МБ (MOM/Portable) остаётся Keenetic Native DNS: Split DNS не внедряется. HOME/WORK сохраняют уже работающий Split DNS.
- Запрещено публиковать subscription URL, UUID, ключи Reality, shortId и полные конфигурации в журналах, CI, issues или PR.

## Аппаратная приёмка

1. Подтвердить официальный Release CI `SUCCESS`, опубликованный точный тег и проверяемые SHA256SUMS/артефакты.
2. На каждом из WORK, HOME, MOM выполнить авторизованный read-only updater plan, установку beta.72 с terminal receipt и контроль `/versionz`, `/healthz`, Xray process inventory, DNS plan и VPN transaction doctor.
3. Получить новый read-only VPN runtime-doctor: `catalog_fresh=true` и список имён различающихся полей либо `active_matches_fresh=true`. Существующий mismatch сам по себе не разрешает mutation.
4. Если необходим Refresh, выполнить один штатный guarded Refresh сначала на WORK, с preflight, snapshot, isolated VPN HTTPS, exact post-apply acceptance и rollback. При любой `FAILED/UNKNOWN` — **STOP**, без повторного apply, перезапуска или ручного SSH.
5. Только после успешной WORK приёмки отдельно оценивать HOME и MOM, сохраняя их режимы DNS. Тесты AutoVPN/медиатрафика и UDP-маршрутизация — самостоятельные следующие циклы.
