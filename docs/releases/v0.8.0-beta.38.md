# FreeNet v0.8.0-beta.38

## Что изменилось

### Исправлено зависание окна обновления Xray

После завершения обновления Xray через FreeNet окно «Версия Xray Core» больше не остаётся на устаревшем сообщении «Обновление продолжается». Пока операция выполняется, FreeNet **автоматически** и только для чтения опрашивает квитанцию `GET /api/xray/core/operation`. Как только сервер сообщает `SUCCESS`, `ROLLED_BACK`, `FAILED` или `STOP`, окно отображает реальный итог без дополнительного нажатия «Проверить результат».

- При `SUCCESS` окно обновляет состояние запущенного Xray и версию.
- При `ROLLED_BACK`, `FAILED` или `STOP` показывает соответствующий исход, не объявляя обновление успешным.
- Повторного `POST /api/xray/core/apply` автоматическая проверка **не выполняет**.
- Закрытие окна отменяет опрос; при возвращении FreeNet считывает актуальную квитанцию.
- При длительной недоступности результата автоматический опрос останавливается и оставляет ручную кнопку «Проверить результат». Тайм-аут интерфейса **не считается** неудачей Xray.

### Проверка на Portable

На FreeNet beta.37 аппаратно подтверждён успешный переход Xray `v26.9.9 → v26.10.21` (`SUCCESS / rollback=NOT_NEEDED`, правильный runtime GID `11111`). Зависший индикатор beta.37 был **ошибкой обновления статуса интерфейса**, не повторной установкой и не новым зависанием Xray.

## Ограничения

Изменяются только интерфейс Xray, его браузерные тесты и версия FreeNet. Сам Xray, XKeen, VPN-профили, DNS, routing policy и секреты не меняются. **XKeen UI не требуется.** Отдельные несоответствия активного VPN-профиля и DNS/filter-engine не входят в этот PR.
