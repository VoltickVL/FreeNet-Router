# FreeNet v0.8.0-beta.46

## Что изменилось

### Control Center: версия XKeen сразу, отдельная иконка

[PR #1251](https://github.com/VoltickVL/FreeNet-Router/pull/1251) MERGED, 4/4 terminal PR CI SUCCESS, MERGE SHA `60bf5c6f049ddd32240965a135145c9b0f22e0dc`.

- Версия установленного XKeen выводится в верхней панели **автоматически при входе в FreeNet** из локального авторизованного read-only `GET /api/xkeen/installed`. Открывать меню XKeen ради появления номера больше не нужно.
- Проверка выполняется независимо от загрузки версии Xray, с ограниченными повторами при временной ошибке/тайм-ауте. После повторного входа или восстановления сети показ пересчитывается; ответы старой сессии не могут заменить новый статус. При недоступном API показано «недоступно», а не вечное «версия…».
- Xray сохраняет иконку ядра (шестигранник); XKeen получил самостоятельную пиктограмму шестерни.
- У XKeen и Xray разные кнопки, обработчики, модальные окна и назначения. Автоматическая загрузка версии — только **GET**, без вызова update/plan/apply/restart, подписки и изменения VPN/DNS/routing.

### Тесты и ограничения

4/4 PR CI terminal SUCCESS: [Router](https://github.com/VoltickVL/FreeNet-Router/actions/runs/40604629079), [Production Browser](https://github.com/VoltickVL/FreeNet-Router/actions/runs/40604629060), [Config Studio](https://github.com/VoltickVL/FreeNet-Router/actions/runs/40604629015), [Routing](https://github.com/VoltickVL/FreeNet-Router/actions/runs/40604629067).

VM и браузерные тесты воспроизводят login без клика, поздний DOM mount, 503/401, timeout, ограниченный retry, повторную авторизацию, восстановление соединения, remount и различие SVG. Все фоновые запросы XKeen остаются read-only.

Сохранено исправление AutoVPN из beta.45 (подтверждённый HTTPS media stall при HTTP 200 и curl timeout учитывается в наблюдениях). **Реальный AutoVPN failover не признан успешным**: на lunatikvl были повторные media stalls и STOP из-за неподтверждённого кандидата, на Portable ранее обнаружен `routing-gid-mismatch`. Ни эта UI-правка, ни выпуск релиза не выполняют Xray core update, XKeen update или VPN/DNS/routing mutations.

На lunatikvl перед выпуском подтверждены FreeNet beta.44, XKeen 1.1.3.9 Stable, Xray v26.9.9 и `xray/process-inventory.restart_ready=true`. Проверка официального обновления XKeen через роутер возвращала `upstream-check-unavailable`; это отдельный runtime-дефект, данным UI PR он не исправлен. Штатная установка beta.46 на устройства и acceptance после неё требуют отдельного безопасного цикла.
