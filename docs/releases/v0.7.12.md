# FreeNet Router v0.7.12 — подключение ChatGPT через официальный OpenAI Tunnel

## Что изменилось

### Управляемый OpenAI Tunnel

- В **Администрирование → Доступ и диагностика** добавлен браузерный мастер: tunnel ID уже созданного туннеля OpenAI Platform, **Runtime API key только с правами Tunnels Read+Use**, сохранение, **запуск / остановка / проверка состояния / удаление ключа**.
- Установка клиента остаётся отдельным явным подтверждением: используется официальный зафиксированный **OpenAI tunnel-client v0.0.16**, проверяемый по HTTPS, SHA256, ZIP/ELF/архитектуре и точному `--version`. После установки сохраняется локальная аттестация SHA256; запуск запрещён без неё и без повторной проверки.
- Ключ и машинный Bearer хранятся только на роутере в закрытых файлах с правами `0600`, а конфигурация клиента содержит ссылки `file:`, но не секреты. **Не используйте Admin key**. Существующее или противоречивое состояние не перезаписывается автоматически.
- Клиент работает исходящим HTTPS-соединением с OpenAI, без нового входящего WAN-порта. FreeNet контролирует дочерний процесс, локальный `/readyz`, ограниченное восстановление и явное отключение. При неизвестном состоянии — STOP. Перед запуском необходимы подтверждённые ABI, установленный проверенный бинарник и не менее 128 МиБ доступной памяти.
- Статусы **локальный процесс**, **локальная готовность клиента** и **подтверждённое подключение плагина ChatGPT** намеренно разделены: готовность `/readyz` сама по себе не доказывает end-to-end ChatGPT.

### Временный доступ из ноутбука

- MCP получил `request_access` и `get_access_status`. Без согласия владельца диагностические инструменты FreeNet по постоянной машинной identity **недоступны**.
- В Администрировании можно увидеть запрос, **одобрить на 15 минут**, отклонить и немедленно **отозвать**. Запрос истекает без ответа. При остановке/потере процесса или перезапуске FreeNet одобрение сбрасывается; никакого raw shell или команд изменения маршрутов не добавлено.
- Для действительной удалённой авторизации нужен **доступный с ноутбука безопасный HTTPS Control Center**, существующая admin-сессия FreeNet и корректный same-origin. Наличие браузерного FQDN в домашней LAN **не доказывает** внешнюю доступность.
- Разрешение относится к этому туннелю/рабочему пространству ChatGPT. Не предоставляйте доступ к нему недоверенным участникам workspace. Отзыв локального ключа во FreeNet **не отзывает** Platform key автоматически: его можно отдельно отключить в OpenAI Platform.

### Подключение через ChatGPT

После штатного обновления и явной установки проверенного клиента: откройте браузерный мастер FreeNet, введите Tunnel ID и ограниченный Runtime API key, сохраните, запустите, проверьте `/readyz`, затем добавьте пользовательский MCP-плагин ChatGPT в том же workspace с типом подключения **«Туннель»** и настройкой **No authentication** на стороне ChatGPT. Внутри роутера статические MCP-запросы требуют отдельного секретного локального заголовка; это не публикация MCP наружу.

**Первое реальное соединение ещё НЕ проверено:** на устройстве с v0.7.11 был успешен лишь read-only preflight: linux/arm64, около 565 МиБ доступной RAM, 12067 МиБ в `/opt`, `EXEC_FLAG_ALLOWED`, клиент `ABSENT`. Реальная установка OpenAI ELF/ABI, доступность OpenAI control plane, Runtime API key/Tunnels Read+Use, успешный `initialize`/`tools/list`/`request_access`/`get_status` и внешний ноутбук требуют runtime-приёмки уже на этой версии.
