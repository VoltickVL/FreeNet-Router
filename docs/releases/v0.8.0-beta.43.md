# FreeNet v0.8.0-beta.43

## Что изменилось

### Достоверная диагностика Xray без опасных догадок

На работающем существующем XKeen/Xray стекe Xray может быть online, но защищённая проверка принадлежности процесса — `unknown-xray-process`. Теперь `GET /api/xray/process-inventory` показывает **конечные безопасные причины** `reasons: [{code,count}]`: недоступность сведений о процессе, несовпадение конфигурации, routing GID, binary inode или недоверенный alias. Идентификаторы процессов, пути, окружение, ключи и пользовательские конфиги в API не публикуются.

Строгая защита **не ослаблена**: неизвестная роль Xray по-прежнему блокирует небезопасный restart и AutoVPN failover. Новая диагностика помогает установить первичную причину и затем адресно её исправить, не убивая работающий Xray. [PR #1246](https://github.com/VoltickVL/FreeNet-Router/pull/1246).

### XKeen — проверка версии в Control Center

Добавлена авторизованная read-only проверка установленного XKeen и его канала по собственным локальным метаданным, с сопоставлением официальной последней **Stable** из `jameszeroX/XKeen`. Отображается установленная версия, доступная Stable или достоверная ошибка проверки. Совпадение номеров Beta и Stable не считается подтверждением идентичности сборок.

Проверка ничего не устанавливает, не вызывает `xkeen -uk` и не перезапускает Xray. [PR #1247](https://github.com/VoltickVL/FreeNet-Router/pull/1247).

### XKeen рядом с Xray — управляемое обновление файлов

В верхней панели FreeNet рядом с кнопкой Xray появляется **отдельный чип XKeen**. Он открывает собственное окно: проверка, точный план, подтверждение применения, наблюдение за операцией, терминальная квитанция и восстановление при сбое.

Установка безопасно ограничена **пакетом сценариев XKeen** (`/opt/sbin/xkeen`, `/opt/sbin/.xkeen`): официальный GitHub Stable, точный SHA-256 и размер архива, ограниченная безопасная распаковка без symlink/traversal, проверка текущей версии, резервный снимок, последовательное применение и обратное восстановление при ошибке. Вновь запускаемый запрос не может маскировать незавершённый rollback; отсутствие фактов приводит к `STOP`.

**Важная граница:** не запускается штатный upstream `xkeen -uk`, который может перерегистрировать сетевые хуки и перезапустить Xray. В этой версии обновляются только собственные исполняемые файлы/модули XKeen, **без смены работающего Xray, DNS, маршрутов, init и firewall**. Полная миграция системных регистраций XKeen не объявляется выполненной. Если Xray process inventory остаётся `unknown`, применение нового пакета **заблокировано** — работающий VPN сохраняется. [PR #1248](https://github.com/VoltickVL/FreeNet-Router/pull/1248).

### Проверки и безопасность

Все три независимые задачи [#1246](https://github.com/VoltickVL/FreeNet-Router/pull/1246), [#1247](https://github.com/VoltickVL/FreeNet-Router/pull/1247), [#1248](https://github.com/VoltickVL/FreeNet-Router/pull/1248) MERGED после **4/4 terminal PR CI SUCCESS** каждая. Новые Go-тесты охватывают точные причины Xray, неправильную версию/канал, недоверенный архив, SHA-256, TAR overflow, ошибку на стадии замены файлов, возврат исходных модулей и неизменность пользовательских конфигов. Браузерные проверки подтверждают соседство Xray/XKeen и читаемое мобильное/десктопное отображение.

### Границы аппаратной приёмки

Успех CI и GitHub Release **не доказывает**, что новая версия установлена на роутере и что AutoVPN failover прошёл реальное переключение. По последней аппаратной проверке Portable остаётся на beta.41, Xray v26.10.21 и рабочем VPN Франция/Париж. Следующий шаг — только штатный FreeNet plan/manifest/snapshot/apply/receipt для beta.43, затем read-only `/api/xray/process-inventory.reasons`, `/api/xkeen/installed`, `/api/xkeen/update/plan` и клиентская HTTPS/QoE проверка. Другие роутеры не трогать без отдельной safety gate.

P1 #1227 (Xray inventory), #1225 (клиентские HTTPS stalls), #1236 (transparent routing/AutoVPN acceptance) остаются открытыми. Stable/main не менялись.
