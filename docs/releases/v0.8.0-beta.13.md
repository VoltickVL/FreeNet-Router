# FreeNet Router v0.8.0-beta.13 — диагностика lock и вложенного восстановления VPN

## Изменения

Расширен штатный **read-only** `GET /api/vpn/transaction-doctor` (PR #1183, Issue #1182). Теперь он отдельно показывает:

- `lock_state` — отсутствует lock, отсутствует записанный PID владельца, PID существует, но личность владельца не доказана, lock принадлежит протоколу updater или состояние невозможно проверить.
- `recovery_outbound`, `recovery_profile`, `recovery_filter` — состояние **вложенного** `recovery.pending` относительно живых файлов (совпадают/отличаются/повреждены/неизвестны).
- `recovery_core_before` — только разрешённые значения `running`/`stopped` или `missing`/`unknown`, без содержимого конфигов.

При проверке владельца lock используются проверки типа файлов, запрет symlink, ограничение размера PID и повторное чтение. **Отсутствующий PID не является разрешением снять lock:** владелец мог завершиться после изменения живой VPN-конфигурации, а PID мог быть повторно использован.

Данный релиз **не** добавляет endpoint или кнопку принудительной разблокировки, не снимает `STOP_*`, не очищает checkpoint, не запускает/останавливает Xray и не меняет VPN/DNS/routing/AUTO.

## Причина и приёмка

На переносном Keenetic Giga после неудачного ручного переключения Beta11 сохранились исходный и вложенный `PENDING` checkpoint, их содержимое отличается от трёх живых файлов VPN, lock указывает на отсутствующий процесс, а процессный inventory временами содержит дополнительные кратковременные PID Xray. Это **ROLLBACK UNKNOWN**, а не завершённое восстановление. Новая диагностика предназначена для безопасного определения следующего действия без обязательного ручного SSH.

PR #1183: только `vpn_mutation_lock_doctor.go`, `vpn_transaction_doctor.go` и targeted tests; CI **5/5 terminal SUCCESS**, включая Go/router build, основной Browser, Production, Routing и Config Studio. Исходный PR merged в Beta как `5057fd2cc27969b168c32cf774387a5eb06e3797`.

## Установка и ограничения

**Beta prerelease, не Stable.** На переносном Giga остаётся **Beta11 с PENDING/UNKNOWN**, поэтому **не устанавливать Beta13 и не запускать повторное VPN-переключение**, пока отдельный штатный recovery gate не подтвердит безопасное состояние. Публикация диагностического релиза и успешные CI не подтверждают аппаратное восстановление VPN.

На остальных устройствах обновление — только штатным `plan → backup → SHA-256 → staging → apply → post-acceptance → rollback` при отсутствии блокировок и неизвестного runtime; существующие XKeen/Xray, credentials и настройки необходимо сохранять. При FAILED/UNKNOWN — STOP. Stable/main не изменяются.
