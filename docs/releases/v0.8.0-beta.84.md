# FreeNet Router v0.8.0-beta.84

## Что изменилось

### Главное: AutoVPN реагирует на устойчиво плохую передачу видео, а не только на полную потерю HTTPS

Развиваем полноценный **AutoVPN Xray Live Pool**, появившийся в beta.83, вместо отдельной диагностической сборки. После **отдельного безопасного включения пула** в FreeNet Control Center автоматическая система теперь умеет распознать подтверждённое замедление передачи медиаданных через **фактически действующий Xray balancer**, а не ошибочно проверять старый исходный статический сервер.

- **Контроль фактического соединения.** Через локальный SOCKS живого Xray выполняются ограниченные HTTP body-пробы с двумя независимыми источниками. Результаты являются техническим сигналом качества трафика, а не заявлением, что конкретные Instagram Reels или Telegram на клиентском устройстве уже воспроизводятся нормально.
- **Устойчивое подтверждение.** Одиночная медленная загрузка, частичный ответ, неизвестный HTTP-статус, пропавшая сеть или изменение текущего Xray target не вызывают автоматическую смену. Требуются повторные полностью подтверждённые ухудшения с интервалом; для прерывистых лагов — больше наблюдений. Media-сэмплы выполняются не чаще предусмотренного интервала.
- **Проверка резерва.** AutoVPN может переключаться только между уже включёнными узлами ограниченного пула при подтверждённой свежести профиля. Кандидат предварительно проходит HTTPS, проверки сервисов и передачу медиаданных. Исходный `vless-reality` больше не считается исправным резервом только потому, что он «исходный»: перед автоматическим возвратом он отдельно проверяется.
- **Без Xray restart на каждой смене.** После однократного включения пула используется локальный Xray RoutingService; для автоматического медиапереключения необходимы разрешённый Auto Apply/Best, здоровый WAN, свободные locks и отсутствие STOP.
- **Проверка результата и откат.** После изменения реального target повторно проверяются HTTPS и полный медиапоток через живой balancer. Если результат не подтверждён, используется штатный verified rollback; `ROLLBACK FAILED/UNKNOWN` означает STOP. Под блокировкой writer дополнительно перепроверяются SHA текущих конфигураций и фактически выбранный target.
- **Защита от «пинг-понга».** После ручной либо аварийной смены действует часовая пауза именно для media-only оптимизации. Сообщения Control Center различают полную недоступность VPN и деградацию видео при работающем HTTPS.

### Что остаётся неизменным

Обновление **не включает VPN-пул автоматически**, не изменяет ISP/DNS, kernel routing/XKeen rules, порты WAN, пользовательские credentials или подписки и не перезапускает Xray. Первичное включение Xray-пула из beta.83 — отдельная защищённая операция с plan, snapshot, validation и rollback. Если пул не активирован, прежний AutoVPN продолжает работать по существующему механизму. Рабочие настройки роутеров сохраняются.

## Граница готовности

Это содержательная функциональная **Beta**, не Stable. Management сообщил об установке **beta.83 на всех четырёх роутерах**, но независимая runtime-проверка и включение нового Xray-пула не подтверждены. Публикация beta.84 не равна её установке и не доказывает исправление Reels/Telegram, клиентского HTTPS egress или аппаратного rollback. До безопасного пилота не изменять исправно работающую сеть ради проверки новой функции; для неизвестного rollback остаётся STOP.
