# FreeNet Router v0.8.0-beta.14 — защищённый updater для двух незавершённых VPN-транзакций

## Что изменилось

**P0: защищённый возврат управления обновлением FreeNet при осиротевшем общем VPN/network lock** ([PR #1188](https://github.com/VoltickVL/FreeNet-Router/pull/1188), Issue #1187). Релиз дополняет диагностическую Beta13.

Когда обычное обновление упирается в уже существующий VPN/network lock, SHA256SUMS-проверенный updater может перейти к ограниченной процедуре восстановления **только** при явно подтверждённой установке конкретной Beta. Перед любым перемещением lock он проверяет два полных `PENDING` checkpoint, целостность их защищённых копий, сохранённые живые файлы, отсутствие чужого updater marker, числовой PID отсутствующего владельца, отсутствие других процессов-записывателей, повторную неизменность inode и независимый recovery guard. Сначала завершается скачивание и проверка SHA-256 всех компонентов выбранного релиза.

Старый lock **не удаляется**: он переносится в карантин в той же файловой системе, а сведения о переносе сохраняются отдельно. После нового эксклюзивного захвата lock повторно сверяются контрольные суммы VPN/Xray и обоих checkpoint. Только затем выполняется прежний штатный цикл `backup → FreeNet-only apply → restart UI → health/version/hash acceptance → rollback`.

Тесты подтверждают отказ без изменений при живом/повторно использованном PID, другом активном записывателе, чужой блокировке updater, повреждённом PID, неполном вложенном checkpoint, неверной SHA-256 и отсутствии необходимых условий. В этих случаях сохраняется **STOP**.

## Ограничения и безопасность

- Обновляются **только компоненты FreeNet**. XKeen, Xray, VPN credentials, реальные конфиги VPN, ISP, DNS и routing не переустанавливаются и не переключаются.
- Два `PENDING` checkpoint и блокировка AUTO **не очищаются**. Эта версия **не восстанавливает VPN** и не доказывает завершение прежнего rollback.
- На переносном Giga сейчас Beta11, `ROLLBACK=UNKNOWN`, основной и вложенный checkpoint `PENDING`, живые VPN-файлы отличаются от обоих snapshot. Установка Beta14 на Giga допустима лишь через **аутентифицированный Browser Recovery с exact tag и подтверждением Beta** после отдельного read-only preflight. Если проверка условий не пройдёт — STOP, не выполнять SSH cleanup.
- После обновления приложения потребуется **отдельная подтверждённая VPN recovery-транзакция** с candidate validation, проверкой VPN HTTPS/path и rollback. Не включать AUTO или повторный manual switch до её принятия.
