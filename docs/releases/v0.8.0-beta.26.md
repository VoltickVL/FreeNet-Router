# FreeNet Router v0.8.0-beta.26

## Best Server: восстановление достоверного подбора при кратковременных сетевых сбоях

- При **ручном подборе серверов** и явной проверке текущего VPN добавлен **ровно один повтор** HTTPS-пробы только того сервиса, у которого наблюдался кратковременный транспортный сбой (TCP connect timeout/временная ошибка соединения). Остальные успешные сайты не перепроверяются. Жёсткий лимит сервисного этапа **8 секунд** сохранён, каждая отдельная попытка ограничена **3 секундами**.
- **HTTP 403/405/429/5xx не превращаются в успех и не запускают повторную попытку**: наличие ответа с ограничением сервиса не приравнивается к временному транспортному сбою. Недоступный исполняемый файл, неизвестная ошибка и отмена проверки не становятся подтверждённым отказом. Правило допуска **4/4** сохраняется; подтверждённый неуспех повторной проверки по-прежнему блокирует рекомендацию.
- **AUTO VPN, его периодические наблюдения, маски сервисов, аварийное восстановление и антифлап не изменены**. Новая повторная проверка используется только в интерактивных замерах качества; она не включается в фоновый AUTO-путь.
- В Control Center появился отдельный раскрываемый раздел **«Почему не подошли другие серверы»**: до трёх *фактически измеренных* отклонённых вариантов с безопасными причинами и доступной только диагностикой/повторной проверкой. Они не занимают слоты «Топ-3 подходящих», не могут быть применены через этот список и не получают действующий apply-допуск.
- Если найдено **0 пригодных** кандидатов или срок 360 секунд исчерпан, интерфейс показывает именно 0 и причины отказа, не подменяя их количеством отклонённых вариантов и не скрывая диагностическую сводку за общей надписью «подбор завершился по лимиту».
- Сохранены режим DNS, ISP policy, правила маршрутизации, прямой доступ, Xray/XKeen и текущий VPN. Подбор не инициирует автоматическую смену активного профиля.

**Граница приёмки:** проверка доступности главных HTTPS-страниц Telegram/Instagram **не измеряет** непосредственное буферизование видео и пути всех медиасерверов. Этот выпуск снижает ложное отбрасывание профилей и раскрывает причины отбора, но сам по себе **не доказывает устранение заиканий видео** и не подтверждает исправность конкретного VPN-выхода. Для реального определения причины нужна read-only проверка фактического клиентского маршрута/качества доставки медиатрафика в Control Center.

## Проверки

- Детерминированные Go-регрессии без внешней сети: однократный transient failure → повторная успешная HEAD, повторный отказ, HTTP 403 без повтора, TLS/startup unknown, неизменное одно наблюдение на сервис в AUTO, ожидание завершения дочерних процессов.
- Контракты разделения «Топ-3» и read-only diagnostics; не показывать action apply для отклонённых; не превращать ноль пригодных в ненулевой результат при наличии diagnostics; partial не скрывает причины.
- Основной CI, браузерные проверки, сборка для MIPSLE и release acceptance обязательны до merge и публикации.

**Установка:** выпуск не меняет реально работающий Portable до отдельного штатного update plan → manifest/SHA → backup → apply → health/version/профиль/rollback receipt. Если административная авторизация недоступна или состояние неизвестно — STOP без mutation.
