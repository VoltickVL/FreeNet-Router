# FreeNet v0.8.0-beta.41

## Одна версия для надёжного переключения VPN и восстановления AUTO

Исправления связаны одной задачей: безопасная работа жизненного цикла VPN при исчезновении сервера, диагностических запусках Xray и запаздывающих браузерных подтверждениях. Основание: на Portable перестали открываться ChatGPT, Instagram и игровые сервисы через Прагу, но ручное переключение на Францию восстановило доступ с телефона. У мамы переключение блокируется `multiple-xray-processes`.

### 1. АвтоVPN снова распознаёт подтверждённый прикладной отказ

- Истечение **собственного ограниченного времени** HTTPS-проверки или явный `curl 28` с живым родительским контекстом учитываются как завершённый отрицательный результат конкретного адреса. Отмена родительской проверки, пропущенный адрес, недостоверная конфигурация и недоступный диагностический процесс остаются `UNKNOWN`.
- Если два независимых HTTPS-адреса через текущий VPN оба не открываются, это неисправность **прикладного VPN-пути**, даже если отдельный IP-транспорт отвечает. Не требуется ошибочно признавать рабочий IP доказательством исправности приложений.
- Никакого переключения по единственной неудаче: обязательны **две независимые законченные проверки**, здоровый обычный WAN, отсутствие незавершённого rollback, защита от одновременных операций, подтверждённый другой профиль и прежние план/снимок/контролируемый apply/post-apply HTTPS/rollback.
- Если обычный speedtest текущего VPN неполный, но имеется повторяемая привязанная к фактическому профилю сервисная деградация, допускается только **сравнение** кандидатов. Это не разрешает само переключение без дополнительной приёмки.
- После успешного ручного восстановления VPN со штатным post-apply HTTPS, подтверждённым состоянием Xray, финализированным checkpoint и handoff FreeNet снимает устаревшую `post_update_guard` для **точной установленной версии**. При `UNKNOWN`/ошибке rollback или незакрытом checkpoint защита остаётся.

### 2. Изолированные Xray не должны оставаться после диагностики

- Неуправляемый временный Xray, который штатный скрипт запускал как **своего непосредственного дочернего** процесса для route-test, теперь завершается и `wait`-ится при любом выходе из скрипта. Его PID очищается; повторные вызовы очистки не сигналят посторонние процессы. Go-owned Xray по-прежнему может завершать только Go-владелец.
- Добавлен защищённый read-only `GET /api/xray/process-inventory` с конечными ролями и причинами: один подтверждённый production, несколько production, живой изолированный probe, зомби или неизвестный процесс. В ответе нет PID, команд, секретов или путей.
- **Второй неизвестный или реальный production Xray не уничтожается по догадке.** Система останавливает mutation, сохраняет исправный процесс и даёт отдельную доказательную причину. Без подтверждения роли невозможно безопасно выбирать, кого останавливать.
- Runtime watchdog перед автоматическим controlled Start повторно сверяет `/proc` **под эксклюзивной мутационной блокировкой**: запуск допустим только когда подтверждено отсутствие всех Xray. Если основной процесс не удалось распознать, несколько процессов, активный probe либо zombie — новый Xray не запускается, в журнал идёт конечная причина и сохранённый retry backoff. Это предотвращает новый дубль из-за ложного offline.
- Существующая проверка `core_restart_preflight`, ожидание остановки старого PID перед `XKeen -start`, изоляционный замок probe и fail-closed по-прежнему обязательны. Нижеописанное исправление не включает ручной перезапуск Xray и не разрешает дубль.

### 3. Окно ручного выбора VPN завершается по фактическому состоянию

- При зависшем AJAX-запросе выводится «Выбранный VPN уже активен», если read-only `/api/status` однозначно подтверждает **точное имя профиля и endpoint**, запущенный Xray и отсутствие текущей операции. Идентичного IP недостаточно: несколько стран могут использовать один сервер.
- Результат `UNKNOWN` или неизвестный rollback **никогда** не заменяется оптимистичным успехом; повторный Apply не отправляется из polling/рендера.
- После терминального подтверждения отображается завершённое подключение. Ошибочное отсутствие данных приводит к явному STOP, а не бесконечному «Подключаем…».
- Исправление UI не изменяет сервер, DNS, VPN-профили и routing policy.

### Проверки и ограничения

В CI добавлены/обновлены Go-тесты отрицательных и отменённых HTTPS-проверок, двойного AUTO admission, safe handoff после ручного восстановления, классификации процессов Xray (production/probe/unknown/zombie), shell-тест завершения только принадлежащего скрипту диагностического Xray и браузерный тест незавершённого POST/идентичности профиля/UNKNOWN без повторной mutation.

**Аппаратная приёмка после выпуска обязательна:** сначала отдельный read-only инвентарь у мамы, затем только при однозначной роли процессов безопасный recovery; на Portable сохранять работающую Францию, проверить статус окна и AUTOVPN без искусственного отключения сервера. Текущая работоспособность ChatGPT/Instagram/игрового UDP на любом другом роутере не доказана CI. Ошибка `multiple-xray-processes` у мамы не считается автоматически устранённой лишь потому, что обновлена версия FreeNet.

Пользовательские DNS-политики, основной Xray, VLESS credentials, ISP/routing presets и другие роутеры этим релизом самовольно не меняются.
