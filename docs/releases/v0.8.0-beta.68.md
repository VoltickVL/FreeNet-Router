# FreeNet Router v0.8.0-beta.68

## Что изменилось

### Защищённая совместимость DNS plan с официальным XKeen 2.1

- [PR #1298](https://github.com/VoltickVL/FreeNet-Router/pull/1298) merged (`d9b4e345f9982533433647afe4d9b11c15749989`), 4/4 terminal PR CI **SUCCESS**: Router CI `41577649345`, Routing Browser `41577649285`, Config Studio Browser `41577649364`, Production Browser `41577649437`.
- Исправлена ложная классификация штатно запущенного Xray официального XKeen 2.1 с GID `0` как неисправного только потому, что старая DNS-проверка принимала исключительно GID `11111`.
- Read-only helper возвращает `XRAY_IDENTITY=owned` только после строгой проверки единственного production Xray: точный inode установленного бинарника, конфигурационный каталог, все поля GID, отсутствие признака диагностического процесса. Пропавшее доказательство, неизвестная идентичность и посторонний GID остаются STOP. Это не изменение GID процесса и не разрешение произвольного root-процесса.
- Добавлены регрессионные тесты для подтверждённых/неподтверждённых GID `0/11111`, Native/Split DNS и legacy synthetic plans. Первичный FAIL CI от старых synthetic fixtures исправлен на основании реального Actions log; окончательные 4/4 CI — SUCCESS.

## Область применения и безопасность

- Выпуск исправляет **классификацию** процесса в read-only DNS plan, но не выполняет DNS/Xray/VPN mutations и не меняет credentials, подписки, policy routing, маршрутизирующие метки или ISP preset.
- На WORK в beta.67 фактически найдено отдельное расхождение: `dns-proxy intercept=on` при выбранном Split DNS, `dns-routing=split-intercept`. Новый код сам не отключает intercept; для восстановления нужен последующий **отдельный штатный guarded Split repair** с snapshot, preflight, postcheck и rollback.
- Read-only WORK `/api/vpn/runtime-doctor`: 50 fresh profiles, isolated HTTPS PASS, но active outbound stale/mismatched. Клиентский VPN и AutoVPN этим релизом не признаны исправленными.
- Изучены независимо [Xkeen-UI DNS-over-VLESS](https://github.com/umarcheh001/Xkeen-UI/blob/main/docs/dns-over-vless.md) и [XKeen Panel](https://github.com/Dearonski/xkeen-panel) как технические ориентиры для будущей проверки реального DNS-пути, SOCKS-based VPN health, passthrough TXT/HTTPS и failover. Чужой код в beta.68 не копировался; несвязанные функции не смешивались в этот PR.
