# FreeNet Router v0.8.0-beta.68

## Что изменилось

### WORK: корректное определение доверенного Xray с GID 0 при проверке DNS

- [PR #1298](https://github.com/VoltickVL/FreeNet-Router/pull/1298), merge `d9b4e345f9982533433647afe4d9b11c15749989`; все четыре workflow PR CI terminal SUCCESS.
- Исправлено ложное требование исключительно GID 11111 в read-only плане Native/Split DNS. Официальный XKeen 2.1 запускает штатный Xray с GID 0; теперь допускается GID 0 либо 11111, **только** когда helper подтверждает точный inode установленного Xray, каталог конфигурации, единственный процесс, отсутствие probe и согласованный GID.
- Новое поле `xray_identity=owned|unverified` не раскрывает конфиги, PID или секреты. Неизвестная идентичность, неподтверждённая группа и неполные факты сохраняют STOP. Изменение не даёт разрешения на обновление Xray core или произвольный рестарт.
- Добавлены положительные/отрицательные проверки доверенного GID 0 и обновлены synthetic fixture тестов для обязательного поля identity.

## Ограничение аппаратной приёмки

- На WORK во время диагностики beta.67 Xray работал как один подтверждённый production процесс GID 0, однако Split DNS не был активен по сетевому плану: `native-intercept=on`, `dns-routing=split-intercept`. Свежий VPN endpoint проходил isolated HTTPS, но `active_outbound_stale_or_mismatched` не означал успешный действующий VPN.
- Выпуск beta.68 **не** меняет router DNS/Xray/VPN/routing автоматически. Перед исправлением Split DNS требуется штатный авторизованный read-only plan, защищённый snapshot/rollback и post-apply acceptance; проверка клиентского DNS A/AAAA/TXT/HTTPS/SVCB обязательна. Не повторять apply при FAILED/UNKNOWN.
- Существующий Portable `FAILED_UNKNOWN` по #1236 остаётся отдельным STOP. Никаких изменений Portable/Home/Mom данным релизом.
