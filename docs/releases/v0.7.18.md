# FreeNet Router v0.7.18 — служебный веб-мост восстановления

## Что изменилось

- Добавлен совместимый путь выхода из `v0.8.0-beta.1`, когда незавершённая VPN-транзакция блокирует обычное обновление. Используется уже установленный независимый FreeNet Recovery, а не SSH, терминал XKeen или команды Netcraze.
- При переходе **из Beta в v0.7.18** проверенный установщик заменяет только два файла приложения: бинарник FreeNet UI и self-update helper. Существующие VPN/provider-помощники Beta, конфигурации и ключи Xray, XKeen, DNS, маршрутизация, cron, настройки автоматизации и VPN checkpoint сохраняются. Резервное копирование, проверка SHA-256 и rollback остаются обязательными.
- В промежуточном процессе при прежней Beta или незавершённой VPN-транзакции работает **только защищённая страница Recovery**. Старый AUTO VPN, watchdog и CLI-команды планировщика не запускаются. Нет shell-терминала, API удаления checkpoint или обхода авторизации.
- Из Recovery можно проверить точный `v0.8.0-beta.5` без установки и затем отдельно подтвердить переход на Beta. Неизвестный, активный или неуспешно откаченный updater остаётся STOP.
- Чистые Stable-установки без аварийного/Beta-состояния сохраняют обычный интерфейс; автоматического перевода пользователей Stable на Beta нет. Вся Beta не перенесена в Stable.
- Проверены исходный обработчик старого Recovery при VPN blocked, фактический старт ограниченного процесса, запрет CLI и API мутаций, авторизация и точное согласие Beta, двухэтапная дельта файлов, rollback и воспроизводимая упаковка установщика.

## Для заблокированной Beta1

Открыть `/recovery` на том же адресе FreeNet. Использовать существующий пароль администратора. Сначала проверить, что доступен именно **v0.7.18**; не устанавливать вместо него старый v0.7.17.

Кнопка **«Восстановить механизм обновления»** загружает новый проверенный helper и выполняет первый переход. После перезапуска FreeNet открывается страница **«Безопасный переход с прежней Beta»**. Дождаться `STATE=SUCCESS`, затем проверить точный Beta5 и отдельно подтвердить его установку.

При ошибке SHA, загрузки, резервного копирования или неизвестном rollback — остановиться и сохранить показанное сообщение. Не сбрасывать checkpoint, не перезапускать Xray и не повторять применение вслепую.

После Beta5 отдельно проверяются VPN transaction doctor, явный ручной выбор сервера, HTTPS через VPN и интернет на клиентском устройстве. Обновление FreeNet само по себе не означает восстановления VPN или LAN.

## Граница приёмки

Это maintenance-релиз совместимости Recovery. Проверки исходников и fault-injection не заменяют аппаратную приёмку: восстановление интернета на конкретном роутере должно быть подтверждено отдельно. Beta5 остаётся экспериментальным релизом, установка которого требует явного согласия.
