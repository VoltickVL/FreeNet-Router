# FreeNet v0.8.0-beta.62

## Что изменилось

### XKeen 2.1 и FreeNet: исправлен конфликт GID при обновлении Xray

- [PR #1286](https://github.com/VoltickVL/FreeNet-Router/pull/1286), 4/4 terminal CI SUCCESS, merge `6a6f42e0fdd90ac37c7df6d6775b2d298bf05c8c`.
- FreeNet распознаёт штатный Xray, запущенный **XKeen 2.1 с GID=0**, и Xray, запущенный собственным менеджером FreeNet с **GID=11111**. Проверяются все четыре Linux GID, они должны совпадать; прочие и смешанные значения запрещены.
- Одного GID недостаточно для доверия: обязательны точно установленный inode исполняемого файла, соответствующий `XRAY_LOCATION_CONFDIR`, один production Xray и отсутствие нераспознанных, диагностических и zombie-процессов.
- Одинаковая проверка применяется в Core Update/Recovery, XKeen Update gate, read-only инвентаризации Xray и сетевых native/legacy preflight. После атомарной замены бинарника менеджер различает прежний, пока ещё работающий executable (`(deleted)`) и новый процесс; postcheck подтверждает новую версию и process identity.
- Добавлены негативные и позитивные тесты GID 0/11111, смешанных групп, чужого конфигурационного каталога, другого бинарника, дублирующихся процессов и сетевого STOP без изменений.
- Ни маршруты VPN, ни `sockopt.mark`, ни конфигурации с ключами, ни init-скрипт XKeen автоматически не переписываются этим обновлением.

### Безопасность обновления

Само обновление **FreeNet** не перезапускает Xray и не меняет VPN/DNS/routing. Xray 26.10.21 → 26.10.31 на Portable — отдельная контролируемая операция после read-only приёмки новой FreeNet: inventory `ready`, snapshot, guarded apply, health/postcheck и rollback при ошибке. Если state неоднозначен — STOP без принудительной замены, reboot и слепой повторной попытки.

### Совместимость

Keenetic/Netcraze с Entware, XKeen 2.1 и Xray. Устанавливается через штатный FreeNet Control Center без ручных SSH-команд. Не переустанавливает исправный XKeen/Xray.
