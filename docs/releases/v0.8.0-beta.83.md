# FreeNet Router v0.8.0-beta.83

## Главное: управление VPN-пулом без перезапуска при каждой смене сервера

В **FreeNet Control Center → Настройки → AUTO VPN** добавлен защищённый Xray-пул для текущего VLESS Reality и одного-двух резервных серверов. Теперь можно через браузер подобрать измеренные доступные резервные профили, увидеть план, **отдельно подтвердить однократное включение пула**, посмотреть состояние, выбрать конкретный сервер и переключиться без рестарта Xray/XKeen. Ручная команда SSH не нужна.

После включения AutoVPN отслеживает реальный HTTPS через локальный SOCKS-вход активного балансировщика. При **двух подтверждённых отказах HTTPS на фоне работающего WAN**, при включённых Best/Auto Apply и отсутствии STOP/cooldown, FreeNet может переключиться на разрешённый проверенный резерв посредством Xray RoutingService `OverrideBalancerTarget`, не меняя файлы конфигурации и не перезапуская Xray при каждом переключении. Перед переключением проверяются состояние пула, текущая идентичность Xray, свежий источник профилей, точный состав разрешённых исходящих узлов и HTTPS-доступность кандидата. При неудаче применяется обратимый возврат прежнего override; неизвестный rollback = STOP.

### Почему однократное включение требует осторожности

Xray не может выполнить runtime-переключение на сервер, которого ещё нет в запущенной конфигурации. Поэтому при **первом** явном включении FreeNet готовит ограниченный пул: текущий `vless-reality` плюс проверенные резервные VLESS Reality TCP/RAW, локальный Xray API только на `127.0.0.1` и loopback-only SOCKS-вход для фактической HTTPS-проверки. Применение требует одного контролируемого **core-only restart Xray**, способного кратковременно прервать рабочие соединения. Это не происходит автоматически при установке beta.83.

Перед применением выполняются точные проверки текущего Xray, избранных профилей и полного candidate `xray run -test -confdir`, создаётся приватный долговечный checkpoint. Изменяются только управляемые Xray outbounds/routing; ISP/DNS и правила на WAN не меняются. После рестарта исходный подтверждённый сервер закрепляется через API, выполняется HTTPS-проверка. Для отмены пула в UI предусмотрена отдельная операция восстановления исходной конфигурации с защищённым возвратом.

### Защита

- Источники неизвестной структуры, пересекающиеся/чужие balancers, неподдерживаемые транспорты, повторяющиеся JSON-ключи, невалидные/устаревшие профили и чужая занятная операция — **STOP без сетевой mutation**.
- Xray API доступен только локально на роутере; доступ из WAN не открывается.
- Legacy provider switch/refresh, routing/DNS apply и прямое изменение Xray-конфига блокируются, пока активен пул или незаконченная транзакция. Любой UNKNOWN/FAILED rollback блокирует новые операции.
- Изолированные preflight, приватные конфигурации и снимки не записываются в GitHub/issues или UI с секретами.
- **Не применяется автоматически** на WORK, HOME, MOM, Portable и не переустанавливает XKeen/Xray.

## Граница готовности

**Это функциональная Beta с ручным включением**, а не Stable и не доказанный fix Instagram Reels. Нынешний автоматический failover реагирует на **полное подтверждённое нарушение HTTPS**, а не на каждую буферизацию видео: длительная клиентская QoE-проверка, медиа-инциденты, реальный switch на разных роутерах, совместимость со всеми установленными версиями Xray и rollback после реального сбоя остаются открытыми до аппаратной приёмки.

Если на роутере сейчас интернет и видео работают нормально, не включайте пул только ради эксперимента. Установка обновления сама по себе не переключает VPN и не делает первый core restart.
