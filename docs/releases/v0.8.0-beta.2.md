# FreeNet Router v0.8.0-beta.2 — восстановление VPN после аварийного переключения

## Что изменилось

- **Ручной выбор VPN теперь может вывести FreeNet из незавершённой AUTO VPN-транзакции.** При целостном защищённом checkpoint и известном состоянии запущенного Xray пользователь выбирает конкретный Extra-сервер и нажимает «Подключиться». FreeNet сохраняет оба состояния — старый аварийный snapshot и фактические текущие конфиги — проверяет выбранный Xray, применяет только VPN-профиль, выполняет core-only restart, HTTPS acceptance и атомарно передаёт новый сервер обратно AUTO VPN.
- **Безопасное завершение аварии:** после подтверждённого HTTPS два комплекта старых snapshot архивируются; pending checkpoint закрывается, AUTO VPN снова работает с выбранным вручную сервером. При ошибке попытка откатывается к состоянию перед ручным переключением, исходный checkpoint остаётся, продолжение запрещено. Если checkpoint неполон, повреждён, осталась незавершённая вторая операция или процесс Xray неоднозначен — STOP с указанием причины.
- **Проверка Xray и rollback:** причины неуспешного core start и этапы `files/core/VPN` записываются отдельно, а первоначальная ошибка не теряется за общей строкой `provider profile apply failed`. В журнале появился read-only VPN transaction doctor: совпадения out/profile/filter, факт запущенного Xray и явное решение STOP без раскрытия конфигурации или токенов.
- **AUTO VPN меньше реагирует на ложные аварии.** Успешный HTTPS через VPN при недоступности отдельных медиа-сервисов — предупреждение QoE, не подтверждение `VPN_DOWN`. Частичные/неопределённые результаты и DNS/TLS/timeout отдельно от доказанных отказов; прежние safe WAN gate и двойное подтверждение сохраняются.
- **Browser Recovery принимает точный Beta-релиз.** Если активный VPN checkpoint блокирует обычный updater, пользователь может выбрать конкретную Beta, подтвердить аварийный Recovery, а FreeNet проверит SHA-256 опубликованного helper и установит только FreeNet-owned assets по штатной схеме backup/apply/acceptance/rollback. Recovery **не** меняет VPN/Xray/XKeen/DNS/routing и **не** снимает незавершённый VPN checkpoint; собственный неизвестный rollback updater остаётся STOP. Обычный Recovery без выбранного Beta по-прежнему относится только к Stable.

## Ограничения и аппаратная приёмка

**Это тестовый Beta-релиз, не Stable.** CI, shell fault injection и browser tests подтверждают программные контракты, но не заменяют проверку на настоящем Keenetic/Netcraze. Для существующего аварийного MOM на `v0.8.0-beta.1` исходный `ROLLBACK FAILED/UNKNOWN` ещё не разрешён: новая версия сама не делает переключение и не удаляет checkpoint. После доставки требуется фактическое ручное подключение в Control Center, проверка маршрута VPN для LAN-клиента, статуса Xray и продолжения AUTO.

**Ограничение первого обновления с Beta1:** Recovery, уже установленный в Beta1, знает только последний Stable и не может выбрать этот Beta2. Новая функция exact Beta Recovery заработает **только после установки Beta2**. Поэтому из аварийной Beta1 нужен отдельно проверенный и согласованный способ первой доставки (bootstrap/authorized recovery bridge), без переустановки XKeen/Xray и без очистки checkpoint. **Не запускать старый Recovery как способ получить Beta2 и не делать слепой downgrade.**

## Способ распространения

Отдельный GitHub prerelease `v0.8.0-beta.2` с бинарниками для поддерживаемых Entware-архитектур, `SHA256SUMS` и русским описанием. Он не заменяет Stable `latest` и не устанавливается на другие роутеры автоматически. Применение на реальном оборудовании — после точной проверки версии, резервной копии и обратимого плана. Изменения не включают UI CSS-рефакторинг из другого незавершённого PR.
