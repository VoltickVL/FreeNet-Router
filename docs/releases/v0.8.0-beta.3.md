# FreeNet Router v0.8.0-beta.3 — проверенная доставка аварийного VPN Recovery

## Что изменилось

- Исправлен `legacy_update_bridge.sh`: он принимает не только Stable `vX.Y.Z`, но и **точно выбранную Beta** `vX.Y.Z-beta.N` с проверкой формата.
- Предварительный `plan` для Beta остаётся read-only. Реальная `apply` для Beta требует отдельного явного `FREENET_BRIDGE_BETA_ACK=yes`; без подтверждения никакая загрузка или установка не начинается.
- Bridge скачивает из выбранного immutable GitHub Release `SHA256SUMS` и `self_update.sh`, проверяет SHA-256, а затем передаёт точный target проверенному штатному updater с `FREENET_UPDATE_BETA_OPT_IN=yes`. Сам updater повторно проверяет релиз, создаёт backup FreeNet-owned assets, применяет обновление, проверяет результат и делает rollback при ошибке.
- Расширены регрессионные тесты: Beta plan, запрет неподтверждённой установки, точный target и opt-in, некорректные Beta-теги. Прежние проверки Stable, SHA mismatch, отсутствующего manifest, повторных скачиваний и exit code сохранены.

## P0 восстановление VPN (унаследовано от Beta2)

Подтверждённый ручной выбор Extra в FreeNet способен выполнить отдельное восстановление после ошибки AUTO VPN и защищённого pending checkpoint: проверить целостность прежних snapshot и live Xray, сохранить второй snapshot, применить выбранный профиль, выполнить core-only restart и HTTPS acceptance. Только при полном подтверждении завершённое состояние принимается как новый baseline AUTO VPN, без изменения ISP/DNS/routing. При UNKNOWN/ошибке rollback FreeNet останавливает операцию без удаления evidence. В Журнале доступна read-only диагностика.

## Важно для перехода с установленной Beta1

Установленная `v0.8.0-beta.1` **не поддерживает exact Beta Browser Recovery** и может блокировать обычный updater при `MUTATION_BLOCKED=yes`. Поэтому **не нажимайте старую кнопку «Восстановить механизм обновления» для установки Beta3**: она ориентируется на latest Stable. Исправленный Browser Recovery становится доступен только после доставки Beta3.

Для первого перехода требуется **отдельно согласованный одноразовый запуск проверенного transport bridge или bootstrap** на реальном роутере после read-only проверки update lock/state, целостности старого checkpoint и доступности release assets. Bridge не снимает VPN checkpoint, не перезапускает Xray/XKeen, не меняет DNS или routing; установка FreeNet по нему не равна автоматическому восстановлению VPN.

**Приёмка на MOM пока НЕ выполнена.** После доставки: Browser → проверка checkpoint/Xray → явный ручной выбор Extra → HTTPS через VPN → проверка LAN → AUTO VPN продолжает работу. При недоступном или неоднозначном состоянии — STOP и PRIMARY ERROR, без слепой повторной мутации.

Это экспериментальный Beta-релиз. Stable `latest` не заменяется. Все изменения поставляются через неизменяемый GitHub prerelease с SHA256SUMS.
