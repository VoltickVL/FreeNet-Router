# FreeNet v0.8.0-beta.58

## Исправление: официальный каталог Xray при HTTP 403 GitHub API

[Технический PR #1272](https://github.com/VoltickVL/FreeNet-Router/pull/1272) устраняет подтверждённый отказ штатной проверки версий Xray на роутере lunatikvl (у мамы). При установленном и работающем **Xray 26.9.9** read-only каталог отвечал:

`reason=xray-catalog-direct-transport; vpn-http-403`

Прямое обращение FreeNet к официальному GitHub API было недоступно; обращение через действующий VPN попадало на HTTP 403. Это был отказ **получения списка версий до Xray mutation**, а не установленная ошибка или поломка бинарника.

### Как теперь устроена загрузка каталога

1. Основной источник остаётся прежним — официальный GitHub API `api.github.com/repos/XTLS/Xray-core/releases`.
2. Только при подтверждённом HTTP 403/429 на этом API через безопасный изолированный текущий VPN FreeNet пробует **другой официальный источник GitHub**: `github.com/XTLS/Xray-core/releases.atom`.
3. Из проверенного XTLS release tag выбирается стабильная версия, а её контрольная сумма берётся **только** из соответствующего официального файла `Xray-linux-<arch>.zip.dgst`.
4. SHA-256 проверяется при скачивании полного ZIP **перед** семантической проверкой кандидата, snapshot, binary swap и restart. Даже при неизвестной заранее длине архив ограничен 128 MiB. Любая чужая ссылка/редирект, отсутствие точного SHA-256, неполный ZIP и недоступный GitHub CDN дают STOP без замены рабочего Xray.
5. Загрузчик не подменяет действующий VPN, не меняет DNS или провайдерский профиль, не использует непроверенные зеркала и не снимает защиту от неоднозначного процесса.

**Что не менялось:** AutoVPN beta.57 (в том числе latency-QoE при зависаниях Instagram), адаптивный Speedtest 200–300+ Мбит/с, XKeen, native core update identity/inventory checks, controlled restart, post-apply HTTPS и rollback.

## Проверки и ограничение

- [PR #1272](https://github.com/VoltickVL/FreeNet-Router/pull/1272): **4/4 terminal CI SUCCESS** (Router, Routing v2, Config Studio, Production Browser), включая Go, rollback/lifecycle, cross-build и негативные тесты неподтверждённых digest и сторонних редиректов.
- Само наличие fallback в релизе **не гарантирует**, что официальный `github.com/releases.atom` и его CDN доступны из конкретной сети мамы. До установки на роутер это UNKNOWN. Если источник тоже отвечает 403/timeout — безопасный STOP и Xray 26.9.9 остаётся работать.
- Следующий аппаратный gate: штатное безопасное обновление **только FreeNet на lunatikvl** до beta.58, терминальный self-update SUCCESS / rollback NOT_NEEDED / healthz=ok, затем **read-only GET каталога Xray**. Если каталог вернулся с валидной версией и SHA256, отдельно проверить process inventory/semantic/snapshot и только потом рассматривать контролируемый Xray update.
- Не обновлять остальные три FreeNet и не запускать Xray apply ради проверки HTTP403. Никаких SSH-команд и «быстрых» ручных подмен Xray.
- Клиентская приёмка Instagram/AutoVPN на beta.57 по-прежнему OPEN, [#1225](https://github.com/VoltickVL/FreeNet-Router/issues/1225). Задача надёжного Xray-core update: [#1236](https://github.com/VoltickVL/FreeNet-Router/issues/1236).

История фактического запроса 403, process inventory и PR/CI — [журнал #7](https://github.com/VoltickVL/FreeNet-Router/issues/7).
