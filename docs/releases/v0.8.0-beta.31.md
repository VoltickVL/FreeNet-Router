# FreeNet Router v0.8.0-beta.31

## Что изменилось

- В обзор FreeNet, в закрытый по умолчанию раздел «Проверка передачи данных с этого устройства», добавлена ручная браузерная диагностика HTTPS-передачи (issue #1225).
- По явному нажатию браузер делает шесть фиксированных загрузок по 1 МиБ с публичного тестового источника `speed.cloudflare.com`. Никаких команд, файлов конфигурации, токенов, VPN-профилей или router mutations не передаёт.
- Выводит именно измеренные исходы: полностью получено X/6, неполные ответы, тайм-ауты/прерывания и неопределённые ошибки DNS/CORS/HTTP; полные пробы сопровождаются минимальным и максимальным временем. HTTP 200 без всех байтов не считается успешным. Есть ручное прерывание, ограничение 12 секунд на каждую пробу и ограниченный объём трафика.
- FreeNet **не утверждает**, что этим проверена работа Instagram, Telegram, ChatGPT или воспроизведение видео. При CORS/HTTP/сетевой неопределённости это не считается доказанным отказом VPN.
- Проверка скрыта до открытия пользователем, не запускается при загрузке Control Center, не меняет AUTO, DNS, routing, endpoint, Xray, XKeen или подписку.

### Проверки

- Playwright browser fixtures: шесть полностью переданных 1 МиБ объектов; HTTP 200 с укороченным телом (5/6 и одна неполная); отсутствие router mutation, отказ от ложного вывода «видео работает».
- Сохранены existing Router/Production Browser/Routing/Config Studio contracts. Выпуск только после terminal CI SUCCESS.

### Что пока не исправляет

Наличие этой проверки не исправляет само по себе периодическое зависание медиа. Наблюдение на Portable beta30: за MagicBook с Wi-Fi пять загрузок по 1 МиБ за ~1,6–1,8 с, одна — 577 216 байт за 12 с, `curl 28`; роутерная 1 МиБ проба ~1,25 с. Необходима сопоставленная клиентская/роутерная серия с фазами и маршрутом перед каким-либо изменением VPN/MTU/QUIC.
