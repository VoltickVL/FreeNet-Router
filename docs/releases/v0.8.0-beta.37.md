# FreeNet Router v0.8.0-beta.37

## Исправлено обновление Xray через FreeNet Control Center

FreeNet использует **тот же механизм перезапуска Xray, что и установленный XKeen UI** — нативный `softRestart`. Теперь обновление ядра не вызывает повторные тяжёлые `xray run -test -confdir` до и после каждого рестарта. На Portable одна такая проверка занимала около 31 секунды; прежняя цепочка ошибочно повторяла её, в том числе при откате.

Порядок штатного обновления стал коротким:

1. Определить установленное ядро и подтвердить живой процесс XKeen/Xray.
2. Скачать официальный архив **по DIRECT** с уже реализованной проверкой SHA-256; проверить архитектуру и точную версию кандидатного бинарника.
3. Сохранить старый бинарник в отдельную резервную копию; выполнить атомарную замену.
4. Через **локальный** `XKeen UI /api/control` выполнить `softRestart`; подтвердить ровно один работающий процесс Xray **из нового бинарника** и реальный GID `11111`, а также версию. Не делать повторных ресурсозатратных семантических запусков во время post-check.
5. При сбое атомарно вернуть предыдущий бинарник и повторить тот же нативный `softRestart` с отдельным ограниченным резервом времени. При доказанном восстановлении — `ROLLED_BACK`; при неподтверждённом — `STOP`.

Нет дополнительного ожидания свободных слотов фоновых read-only Xray-проверок. Диагностическая кнопка `run -test` остаётся доступной по желанию, но больше **не является обязательной частью установки**. VPN-профиль, DNS и routing FreeNet в этом релизе не изменяются.

## Восстановление после старого STOP

Если прежний update завершился `ROLLBACK FAILED`, а Xray затем был фактически восстановлен штатным XKeen UI, в Control Center появилась кнопка **«Подтвердить восстановленный Xray»**. Она сверяет указанную установленную версию, живой процесс, фактический бинарник, GID `11111`, нативное состояние XKeen UI и отсутствие незавершённой VPN-транзакции. Только после успешной проверки снимается устаревшая блокировка дальнейших операций. **Исходная запись rollback FAILED не удаляется и не переписывается на PASS.**

## Границы

- Это исправление механизма установки Xray, а не обещание устранить ранее зарегистрированные HTTPS body stalls (#1225), Extra VPN switch (#1227) и DNS/filter-engine drift.
- Релиз требуется подтвердить CI, затем **одной** управляемой аппаратной установкой на Portable: сначала FreeNet beta.37, затем восстановление доступа после старого STOP и Xray core update. Другие роутеры не обновляются.
- Если запуск новой версии или откат не подтверждён, продукт честно показывает STOP и сохраняет резервную копию. Секреты, конфиги, токены и URL подписок не логируются.
