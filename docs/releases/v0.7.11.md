# FreeNet Router v0.7.11 — проверка совместимости OpenAI Tunnel на роутере

## Что изменилось

### Исправлено

- Установщик официального OpenAI `tunnel-client v0.0.16` больше не требует несуществующее слово `tunnel` в выводе `--version`. Вместо неточного поиска строки сравниваются **точная версия и commit SHA** официального релиза OpenAI. Ошибка выполнения/ABI и несовпадение версии теперь различаются по причине STOP.
- Сохранены ограничения установки: официальный HTTPS и SHA256, безопасная обработка ZIP, ELF/архитектура и запрет неизвестного динамического загрузчика, staged candidate, отсутствие перезаписи существующего файла, no-replace commit и откат при post-commit ошибке.

### Добавлено

- В разделе **«Администрирование» → «Доступ и диагностика»** появилась отдельная кнопка **«Проверить ресурсы роутера»**.
- FreeNet **только читает** факты Linux/arch, доступную RAM из `/proc/meminfo`, свободное место в файловой системе каталога установки, mount `noexec`, наличие/тип существующего клиента и конфигурационную доступность loopback MCP.
- При неподдерживаемом устройстве, неизвестной памяти, `noexec` или непроверенном/опасном существующем файле результат не выдаёт ложную готовность. Значение `HOST_FACTS_OBSERVED` описывает **лишь предпосылки**, а не проверенный запуск.
- Браузерные и Go тесты подтверждают только чтение, защиту API авторизацией, отказ при неизвестном состоянии и отсутствие изменения Xray/VPN/DNS/routing.

## Важные ограничения

- **Туннель с ChatGPT пока НЕ подключён.** Клиент не запускается автоматически, не передаёт токены и не открывает интернет-порты. Наличие OpenAI Platform Tunnel само по себе не даёт GPT доступа к FreeNet.
- Ни приложение, ни GitHub CI не проверили фактическую работу нового бинарника на конкретном Entware/ARM64 роутере. Тест `--version` при следующей подтверждённой установке остаётся обязательным; возможная реальная ошибка ELF/ABI приведёт к STOP.
- Кнопка проверки ресурсов **не выполняет SSH, shell-команды, исходящие HTTPS-запросы, packet capture или перезапуски**.
- Управляемые OpenAI runtime credentials, постоянный защищённый транспорт и кратковременный запрос/одобрение доступа к FreeNet из ноутбука — **следующий отдельный этап**. До него нельзя обещать сценарий удалённого доступа через ChatGPT.
- Не вставляйте OpenAI API key, FreeNet read-only Bearer, данные VPN-подписки или полные конфигурации в ChatGPT, GitHub или диагностические логи.

## Следующий этап

После штатного обновления до v0.7.11 в браузере открыть «Администрирование» → «Проверить ресурсы роутера» и получить реальный результат. Только после анализа фактов — контролируемая установка бинарника и разработка безопасного OpenAI Tunnel lifecycle с удалённым подтверждением диагностических сессий.
