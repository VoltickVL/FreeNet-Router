# FreeNet Router v0.8.0-beta.67

## Что изменилось

## Исправление P0 Portable: BusyBox-safe post-reboot reconciliation

- [PR #1296](https://github.com/VoltickVL/FreeNet-Router/pull/1296), merge `0bb99043267b450fd5ec492a3bb3821eec39fdb1`, terminal Router CI и Browser UI CI SUCCESS.
- На реальном Portable после перезагрузки `reconcile-reboot-plan` из beta.66 безопасно возвратил `READY=no`: предыдущий implementation использовал `stat -c '%Y'`, которого нет в BusyBox v1.37, несмотря на поддержку штатного `stat -t`. Первичный факт: `btime=1793548324`, исходный receipt mtime `1793546446`; обе исходные временные блокировки отсутствуют, старого updater процесса нет.
- Исправлено чтение времени квитанции: новая проверка переиспользует **заранее закреплённое** поле mtime №8 из валидированного `update_file_proof`, использующего совместимую GNU/BusyBox metadata. Неверная форма/нечисловое время — STOP. Никакой записи в квитанцию, подмены блокировки или изменения Xray/VPN во время read-only plan.
- Регрессионный тест явно отвергает GNU-only `stat -c %Y` и требует положительного полного плана reboot при исходном снимке и старом receipt; предыдущие отрицательные сценарии и terminal proof сохранены.

## Унаследовано от beta.66

- [PR #1295](https://github.com/VoltickVL/FreeNet-Router/pull/1295): доказательный `reconcile-reboot-plan` и `reconcile-reboot <receiptSHA256>`, долговечный STOP при `ROLLBACK_FAILED/FAILED_UNKNOWN`, двойной SHA/runtime proof, архивирование исходной квитанции только при terminal SUCCESS.
- [PR #1294](https://github.com/VoltickVL/FreeNet-Router/pull/1294): один ограниченный retry официального Xray release catalog через действующий VPN при разрыве HTTPS stream.

## Аппаратная приёмка — ограничение

- На Portable рабочие FreeNet **beta.63**, Xray **v26.10.21**, вручную выбранная **Дания**. В beta.65 был сбой подтверждения identity нового HTTP daemon; не запускать обычный self-update до отдельного исправления. `ROLLBACK_FAILED/FAILED_UNKNOWN` пока не завершён терминально.
- Для получения этого helper допустима только загрузка из официального неизменяемого GitHub commit/release с точной SHA-256-проверкой, затем `reconcile-reboot-plan` **только чтение**. `reconcile-reboot` допускается исключительно если на устройстве `READY=yes`, полный документированный двойной proof и точный SHA исходного receipt; любое расхождение — STOP.
- Выпуск релиза **не** обновляет Portable, не меняет VPN/Xray/DNS/routing, не обходит safety-gates и не выполняет принудительную очистку аварийного состояния.
