# FreeNet v0.8.0-beta.48

## Что изменилось

### AutoVPN больше не застревает после обновления

Проблема воспроизведена на Portable после штатной установки beta.47: роутер передавал контрольные медиасегменты со скоростью 0,3–6,3 Мбит/с, AutoVPN находил альтернативы, но при совпадении обновления FreeNet с попыткой переключения получал `another FreeNet operation is already running`. Старый код ошибочно считал **этот конфликт до любых сетевых изменений** неизвестным откатом и сохранял постоянную блокировку. Затем при каждом watchdog-проходе полностью подтверждённая деградация видео считалась «неоднозначностью после обновления», поэтому поиск не возобновлялся.

В beta.48 две связанные коррекции:

- [PR #1253](https://github.com/VoltickVL/FreeNet-Router/pull/1253): занятый writer semaphore **до начала применения VPN** возвращает явное `NOT_APPLIED`, а не пустой rollback status, который превращался в `UNKNOWN`. Не происходит изменения Xray, VPN, DNS, маршрутов и флагов отката.
- [PR #1254](https://github.com/VoltickVL/FreeNet-Router/pull/1254): после успешного self-update **две завершённые медленные HTTPS-медиапробы по точно идентифицированному текущему VPN** подтверждают reachable-but-degraded. FreeNet разрешает обычную повторную quality-оптимизацию и сравнение кандидатов; он не требует, чтобы уже тормозящее видео сначала «само стало идеальным».
- Сохранённый ложный флаг beta.47 может автоматически согласоваться **только** при точном старом результате `writer busy before mutation`, отсутствии checkpoint и writer/update lock, подтверждённом успешном обновлении и свежей совпадающей по endpoint/filter identity медиапробе. Настоящий `rollback FAILED/UNKNOWN`, незавершённая транзакция, неизвестный активный VPN или неразрешённое обновление по-прежнему останавливают изменения.
- Сохраняются штатные AutoVPN: повторное измерение деградации, сравнение только проверенных Eligible-кандидатов, одна резервная попытка с отдельным endpoint (beta.47), контролируемое применение, проверка результата и откат при подтверждённой ошибке. Не добавлялись новые бесконечные циклы, ручные SSH-проверки или сбросы состояния.

### Что не менялось

Xray core, XKeen, пользовательские VPN-профили, credentials, ISP/DNS/routing policy и правила провайдера не изменяются самим обновлением FreeNet. Дополнительный VPN на MagicBook-Pro не используется для диагностики роутера и не затрагивается. `routing-gid-mismatch` из `/api/xray/process-inventory` на Portable остаётся отдельной аппаратной диагностикой для **native Xray core update/restart** — она не является доказанным отказом provider apply через XKeen; строгий core-update GID gate не отключён.
