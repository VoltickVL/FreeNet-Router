# FreeNet Router v0.8.0-beta.85

## Что изменилось

### Главное: работоспособное управление AutoVPN Xray Live Pool и понятная диагностика подготовки

В beta.84 при первом реальном домашнем пилоте обнаружились две связанные проблемы: элементы **«Стабильного пула VPN»** в Settings перекрывали друг друга, а «Подобрать резервные VPN» не позволяло определить, на каком безопасном этапе отказалась подготовка. Общий «Журнал» не заменял этой информации. **Beta.85 устраняет именно пользовательскую преграду к безопасной подготовке и отдельному включению уже существующего Live Pool**, а не маскирует отказ случайным повтором Xray.

- **Понятная последовательность действий:** отдельная панель «Стабильный пул VPN» с двумя шагами — «1. Подобрать резервы» и «2. Включить пул», отдельными read-only «Проверить состояние», выбором активного узла, guarded переключением и возвратом исходного VPN. Ничего не активируется без осознанного нажатия и штатной проверки.
- **Адаптивная компоновка:** кнопки, выпадающий список и сообщение о состоянии больше не располагаются в одной общей строке с описанием; блок адаптирован к экранам 320–1440 px. Disabled-кнопки не накладываются на другие элементы.
- **Диагностика подготовки по этапам:** после нажатия на подбор видно «Шаг 1/2: измерение», затем «Шаг 2/2: Xray preflight». Если проверенных резервов нет или сервер вернул конкретный безопасный код отказа (устаревший снимок, HTTPS отказ резерва, несовместимый transport/config, недоступный loopback port, полный Xray preflight failed), интерфейс показывает соответствующую причину, а не общее «Не удалось». При неизвестном ответе состояние явно считается неподтверждённым, без угадывания причин.
- **Безопасная поверхность ошибок:** в UI выводятся исключительно подготовленные русские сообщения из разрешённого списка. Необработанные ответы, access tokens, credentials, IP endpoints и пользовательские конфиги не отображаются.
- **Единый стиль Settings:** иконка раздела «Видео и связь» отличается от значка AUTO VPN; заголовок «Системное обслуживание» выровнен с остальными.

### Что не изменилось

Алгоритм AutoVPN из beta.84, DNS, ISP-политики, маршрутизация, XKeen, Xray, VPN credentials, активный endpoint и подписка **не менялись**. Само обновление FreeNet **не включает Xray Live Pool автоматически и не перезапускает Xray**. Первичная активация по-прежнему возможна лишь после готового плана, отдельного подтверждения, checkpoint/backup, полной validation и одного контролируемого Xray restart; дальнейшие переключения внутри работающего пула идут через API без restart. При STOP/UNKNOWN и неуспешном rollback новые mutations запрещены.

### Граница аппаратной приёмки

На момент разработки Management подтвердил установленную beta.84 на **HOME, WORK и MOM** по снимкам Control Center и отсутствие заметной повторяющейся нестабильности HOME. **Beta.85 ещё не установлена**, её runtime acceptance и успешный Live Pool plan/activate не доказаны. Точная первичная причина отказа подбора на HOME в beta.84 не была получена, поскольку старый UI подавлял диагностический код. Нельзя считать отсутствие пула отказом самого VPN. Для нового пилота сначала использовать read-only подбор и проверку на HOME, без активации сразу на всех роутерах.
