# FreeNet v0.8.0-beta.39

## Что изменилось

### Резервный канал скачивания Xray без изменения рабочего VPN

Исправлен алгоритм получения официального архива Xray на Keenetic/Netcraze. На рабочем роутере FreeNet beta.38 успешно обновился, но отдельное обновление Xray `v26.9.9 → v26.10.21` остановилось **до замены бинарника** с общим сообщением `cannot download selected Xray release`. Существующий Xray, VPN Швейцария и DNS сохранились, `rollback=NOT_NEEDED`.

- Основной канал — прямой HTTPS-запрос с маршрутизирующей меткой `SO_MARK=255`, без системного HTTP/HTTPS proxy. Он остаётся приоритетным.
- При подтверждённой сетевой ошибке, тайм-ауте, HTTP 403/429/451 или HTTP 5xx разрешён **один** резервный запрос к тому же официальному GitHub Release через временный локальный SOCKS5, обслуживаемый изолированным Xray с текущим активным VLESS-outbound.
- Резервный Xray использует только временные файлы с ограниченными правами и отдельный loopback-порт; после получения архива гарантированно останавливается. Основной Xray, DNS, VPN-правила, существующий XKeen и учётные данные не редактируются.
- Если активный профиль нельзя однозначно сопоставить с запущенным VPN либо изолированный запуск не подтверждён, резервный маршрут не используется: **STOP без замены ядра**.
- Отказ SHA-256, неверный размер, неподтверждённая версия, HTTP 404, отмена операции или ошибка integrity **не допускают** резервную повторную загрузку.
- Общая ошибка загрузки заменена на конечные безопасные коды: транспорт/тайм-аут/HTTP-статус, отдельно причины отказа резервного маршрута. Полные адреса, ссылки подписок, ключи и конфиги с секретами в квитанции не публикуются.
- Сохраняются штатные механизмы SHA-256, проверки версии, сохранения предыдущего ядра, controlled restart, post-apply acceptance и rollback. Сетевые изменения через SSH не требуются.

### Проверки

Добавлены Go-тесты прямой загрузки, SHA-256, размера, конечных кодов HTTP, допуска/запрета резервного маршрута, отмены операции и изоляции SOCKS5 от `HTTPS_PROXY`.

## Ограничения

Исправление относится **только** к механизму загрузки Xray. Успех GitHub CI подтверждает алгоритм, но аппаратная установка Xray `v26.10.21` на рабочем роутере должна быть отдельно проверена штатной квитанцией FreeNet. Уже выявленное несовпадение `active_outbound_stale_or_mismatched` и проблемы отдельных клиентских HTTPS-маршрутов этим релизом не исправляются. Stable/main и другие роутеры не изменяются.
