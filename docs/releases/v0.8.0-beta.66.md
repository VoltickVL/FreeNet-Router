# FreeNet Router v0.8.0-beta.66

## Что изменилось

### P0: доказательный rollback FreeNet после перезагрузки

- [PR #1295](https://github.com/VoltickVL/FreeNet-Router/pull/1295), merge `fa8275a623b0f9c524cdc6a7ccc603714ca06fdf`, четыре terminal CI SUCCESS.
- Новые режимы `reconcile-reboot-plan` (только чтение) и `reconcile-reboot <receiptSHA256>` для аварийного `ROLLBACK_FAILED / FAILED_UNKNOWN`, когда предыдущие эфемерные блокировки `/tmp` исчезли после настоящей перезагрузки.
- Терминальная сверка требует одновременно: исходная квитанция старше boot текущего ядра; оба старых lock отсутствуют; нет новых writers; работающий FreeNet совпадает с **официальным FROM release** по точным SHA-256 всех файлов; прежний backup, Xray, подписка и защищённые конфигурации сохранены; независимые проверки подтверждают один результат.
- Только после полного доказательства архивируется исходная квитанция и записывается `FAILED / ROLLBACK_STATE=SUCCESS`. Никаких искусственных lock, перезапуска FreeNet/Xray, сброса DNS, смены VPN или маршрутизации.
- Бэкенд FreeNet теперь блокирует операции VPN/Xray по долговечному `FAILED_UNKNOWN`, даже если после reboot `/tmp` lock исчез. Исправлено различие между фактически работающим updater и сохранённым аварийным состоянием `UPDATING/RECONNECTING/PENDING`. Добавлены тесты положительных и отрицательных сценариев.

### Xray Core: отказоустойчивость чтения каталога обновлений

- [PR #1294](https://github.com/VoltickVL/FreeNet-Router/pull/1294), merge `fb807b9e0f5407832eeebc71c678efed529e8adc`, четыре terminal CI SUCCESS.
- Если поток официального GitHub Xray release catalog оборвался, ошибка сохраняет транспортный тип и допускает один ограниченный повтор чтения **того же официального URL** через работающий VPN.
- Неполный/повреждённый JSON, oversized body, неверная версия, неподтверждённый SHA-256, повторная ошибка обоих каналов — STOP. Автоматической замены Xray и переключения VPN нет.

### Аппаратные факты и ограничения

- На Portable после перезагрузки read-only SSH подтвердил **FreeNet beta.63**, 11/11 корректных SHA-256 официального релиза и backup, 4/4 защищённых файла и 6/6 конфигураций Xray неизменны. Xray **26.10.21**, вручную выбранная **Дания** сохранены. Но прежняя квитанция beta.63→beta.65 ещё `ROLLBACK_FAILED/FAILED_UNKNOWN`: выпуск релиза не равен разрешённой runtime reconciliation.
- Предыдущий updater beta.65 зафиксировал `daemon-start: new HTTP daemon identity was not established` и ошибку identity при откате, хотя beta.65 слушала HTTP-порт. **Обычный self-update на Portable нельзя повторять без отдельной диагностики и исправления этой причины.**
- beta.66 сама не обновляет Xray до 26.10.31, не снимает UNKNOWN и не разрешает AutoVPN в обход safety. [Issue #1236](https://github.com/VoltickVL/FreeNet-Router/issues/1236) остаётся открытой до аппаратной приёмки. [Roadmap #5](https://github.com/VoltickVL/FreeNet-Router/issues/5); [Journal #7](https://github.com/VoltickVL/FreeNet-Router/issues/7).
