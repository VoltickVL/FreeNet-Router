# FreeNet Router v0.8.0-beta.27

## Что изменилось

### GeoData / GeoIP: завершение XKeen больше не означает автоматический успех

- Исправлен подтверждённый риск штатного обновления GeoData: XKeen 2.0 может вывести ошибку отдельной загрузки GeoSite/GeoIP, затем вывести «завершено» и вернуть код 0. FreeNet больше не считает такой результат успешным.
- По **ограниченному объёму** вывода native XKeen -ug FreeNet распознаёт только предопределённые безопасные классы: «источник вернул HTML вместо .dat», «файл слишком мал/повреждён», «не удалось загрузить базу», «нет установленных баз», «обновление не подтверждено», «native завершился с ошибкой». После одного подтверждённого отказа общий результат **failed**, а не success.
- Отдельные положительные подтверждения обновления файлов и штатное завершение XKeen обязательны для признания успешного native-сценария. Если native-вывод отсутствует, переполнен либо не подтверждает запись хотя бы одного файла — **fail closed**, без догадок.
- Запрещена публикация нативного stdout/stderr, URL, конфигураций, токенов и секретов в Journal/API/состояние. Анализ ограничен 256 КиБ памяти. Сообщения об ошибках формируются строго из фиксированного словаря.
- При неуспехе XKeen дополнительно проверяется, сохранился ли исходный статус процесса Xray. Если Xray изменил состояние, возвращается отдельный **STOP**. Общая блокировка FreeNet/Xray и существующие правила координации AUTO остались.
- Никаких дополнительных запусков -ug, повторных рестартов Xray, изменений DNS, маршрутизации, AUTO VPN, подписки, VPN-профиля или core GeoData downloader в этом выпуске нет.

### Проверки

- Детерминированные тесты без внешней сети: выход native 0 при частичной ошибке GeoIP, HTML вместо dat, файл слишком мал, отсутствие баз, пустой вывод, переполнение native transcript, ошибочный exit, нормальная успешная загрузка и отсутствие утечек секретоподобных строк.
- Сохранены штатные тесты блокировки GeoData/Xray watchdog/cron, восстановления и rollback Control Center.
- Публикация проводится только после terminal PR CI SUCCESS и подтверждённого Release SUCCESS с официальными артефактами MIPSLE.

### Границы выпуска и последующие действия

Это **исправление достоверности определения результата и ошибки**, а не переустановка GeoData и не новая загрузочная инфраструктура. Оно не подтверждает, что все файлы .dat актуальны на действующем роутере, и не заменяет проверку содержимого, upstream SHA и rollback. В случае ошибки обновления FreeNet теперь должен показывать безопасную причину для следующего узкого исправления.

Подвисания видео Telegram/Instagram остаются **отдельной runtime-проблемой**. Четыре клиентские мини-загрузки за Portable показали два потока с остановкой на 57–131 КБ и timeout, один TCP connect timeout и один успешный 1-МБ перенос за 1,6 с. Источник общего дефекта DIRECT/VPN/Xray/egress/ресурсов пока не локализован; менять DNS/MTU/сервер без сравнительных маршрутов недопустимо.

**Portable:** по последнему read-only /versionz устройство на v0.8.0-beta.24. Ни beta26, ни beta27 не устанавливались в этом кодовом цикле. Для фактического обновления роутера потребуется штатный plan → backup → apply → health/version/Xray/post-check и rollback receipt.
