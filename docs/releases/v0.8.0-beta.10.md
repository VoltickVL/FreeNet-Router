# FreeNet Router v0.8.0-beta.10 — согласованное обновление GeoData и защита Xray

## Что изменилось

**GeoData/Xray без одновременного восстановления ядра (PR #1174).** Штатный запуск `xkeen -ug` теперь получает тот же межпроцессный mutation lock, который защищает ручные и автоматические VPN-операции. Xray runtime watchdog учитывает этот lock и не запускает конкурирующий controlled Start во время обновления геобаз. Если VPN-операция или обновление FreeNet уже выполняются, GeoData откладываются, не затрагивая рабочий Xray.

**Подтверждение результата, а не только exit code.** После команды GeoData FreeNet сверяет состояние Xray с исходным. При ошибке XKeen или не восстановленном Xray операция отражается как FAILED с безопасным объяснением; положительный результат не выдаётся без этой проверки. При неудаче освобождения блокировки фиксируется STOP. Журналы не публикуют конфиги или секреты подписки.

**Сохранено исправление Beta9 (PR #1170).** Core-only переключение Extra-профиля различает старый live/zombie/reused PID, не отправляет SIGKILL чужому PID и сохраняет fail-closed, durable checkpoint и rollback. Это защита процесса завершения, а не обещание успешного переключения при любой неисправности XKeen/Xray.

Существующие XKeen/Xray и их пользовательские конфигурации не переустанавливаются; изменения DNS, ISP policy и маршрутизации не входят в выпуск.

## Что проверено

Для PR #1174 завершились terminal SUCCESS четыре workflow: FreeNet Router CI `39271011595`, Production Browser CI `39271011666`, Config Studio Browser CI `39271011617`, Routing v2 Browser CI `39271011542`. В targeted Go tests проверены: занятая блокировка, отсутствие ложного GeoData SUCCESS, неуспешный native XKeen, потеря Xray после обновления, конфликт с обновлением FreeNet и удержание runtime watchdog во время длительного GeoData. Критический набор Go/Shell, contract tests и cross-build проходил в Router CI. Публикация этого релиза отдельно требует terminal SUCCESS штатного release workflow.

## Установка и ограничения

Это **Beta prerelease, не Stable**. Для обновления выбрать канал Beta и точный тег `v0.8.0-beta.10`, сначала получить штатный plan, резервную копию и проверку возможности отката. Не обновлять работающий роутер при UNKNOWN/PENDING checkpoint, активной блокировке или неоднозначном состоянии сети.

На переносном Keenetic Giga/MIPS32LE ранее наблюдались ручной VPN FAIL `terminate-old-core/old-core-still-running`, успешный rollback и отдельные кратковременные остановки Xray около планового обновления GeoData. Взаимная эксклюзивность GeoData/Xray исправлена по коду и тестам, но **аппаратная приёмка Beta10, ручного переключения, AUTO failover и долгосрочной устойчивости на Giga ещё не выполнена**. Совпадение по времени GeoData и Xray outage не доказывает единственную первопричину всех инцидентов. После установки нужен контролируемый read-only doctor/runtime acceptance; любые FAILED/UNKNOWN → STOP, без серии повторных переключений.
