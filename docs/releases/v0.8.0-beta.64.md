# FreeNet v0.8.0-beta.64

## Что изменилось

### Аварийная диагностика Xray на существующем роутере (P0)

- [PR #1290](https://github.com/VoltickVL/FreeNet-Router/pull/1290), merge `3eb8f243d95ad51dc51653d3f9b9127366b7d608`: четырe обязательных CI успешно завершены.
- Исправлена чрезмерная блокировка **диагностической** проверки при незавершённом VPN checkpoint. При строго подтверждённом состоянии `pending`, `Xray stopped`, совпадении всех трёх исходных файлов со снимком, отсутствии работающего/неизвестного/probe/zombie Xray и отсутствующем lock/writer разрешено выполнить **только** изолированный `xray run -test` уже установленного бинарника.
- Проверки инвентаризации и checkpoint выполняются дважды, с межпроцессной блокировкой и ограничением времени. Неопределённое состояние, ошибка процесса, другой активный worker либо расхождение файлов = **STOP**, без обхода защитной блокировки.
- Диагностика возвращает конечные безопасные статусы (`valid`, `reason`, `phase`, `child_started`, `exit_code`, `netfilter_hook`, `xkeen_init`) **без stdout/stderr, конфигурации и секретов**. В частности, определяется старый netfilter hook, содержащий ссылку на отсутствующий модуль XKeen 1.x `03_info_cpu.sh`. Никаких файлов не удаляет и не перезаписывает.
- Добавлены targeted unit/HTTP-тесты: совпадение checkpoint, отклонение неизвестных процессов и блокировок, поведение при ошибке Xray, недопустимость утечки credentials и изменений конфигурации.

### Подтверждённое состояние WORK и ограничения релиза

1 ноября 2026 года в системном журнале рабочего Netcraze через встроенный WebCLI `show log` подтверждены 22 записи ошибки старого `/opt/etc/ndm/netfilter.d/proxy.sh` на отсутствующем `/opt/sbin/.xkeen/01_info/03_info_cpu.sh` и 22 соответствующих `exit code 2`. Независимо, последняя защищённая попытка восстановления VPN завершилась `stage=xkeen-start; code=1`, rollback попытки `SUCCESS`. **Причинная связь между двумя кодами пока не доказана**.

На момент выпуска предыдущая аварийная VPN-транзакция на WORK ещё `pending`, Xray остановлен. **Установка самого FreeNet beta.64 не исправляет старый netfilter hook автоматически, не восстанавливает VPN и не удаляет checkpoint**. Не запускать новые `apply`, `restart`, `reboot` до получения диагностического verdict и подготовки отдельного безопасного recovery с snapshot, postcheck и rollback по [Issue #1227](https://github.com/VoltickVL/FreeNet-Router/issues/1227).

### Безопасность и совместимость

Сохраняются XKeen 2.1, имеющийся Xray, DNS, VPN credentials и конфигурационные файлы. Штатный браузерный self-update FreeNet использует прежние защищённые snapshot и rollback процедуры. Изменение не разрешает любые новые операции записи при `PENDING/UNKNOWN` и не превращает Control Center в shell terminal.
