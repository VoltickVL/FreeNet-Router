# FreeNet Router v0.8.0-beta.11 — проверка RTT Extra и диагностика расписания GeoData

## Что изменилось

### Пинг каждого Extra-профиля — надёжный отдельный job (PR #1177)

Ручное нажатие «Измерить задержку через каждый VPN» теперь запускает на FreeNet **один ограниченный read-only RTT job** (HTTP 202) и получает прогресс и результат короткими GET-запросами. Браузеру и CrazeDNS больше не требуется держать один длительный HTTPS-запрос открытым на время проверки десятков отдельных VLESS/Reality-профилей. Открытие/перерисовка списка и синтетическое нажатие не запускают измерение.

- При занятой AUTO health/recovery или другой операции backend возвращает отдельный код `busy` и `Retry-After`; интерфейс выполняет только ограниченные повторы и показывает понятную причину. Проверка не прерывает AUTO recovery, не выполняет Xray mutation и не объявляет недоступными профили, которые не удалось проверить.
- Ответы привязаны к exact logical profile и endpoint подписки; при изменении каталога либо несогласованном измерении результат не применяется к чужому профилю.
- В списке различаются RTT, «нет ответа» для фактически проверенного сервера и «не проверен» для неизвестного результата; при частичном завершении показываются реальные счётчики.
- Проверки безопасности включают single-flight на стороне FreeNet, случайный идентификатор задачи, авторизованный доступ, отсутствие повторных сканов при опросе прогресса, `MUTATION=NONE`, отсутствие секретных настроек в ответах.

Наблюдение на переносном Keenetic Giga до исправления: отдельный вызов старого API 19.10 проверил 48 зарубежных логических профилей, 20 ответили, 28 не ответили, но удалённый интерфейс выдавал общую ошибку RTT. Поэтому это устранение проблемы **длительного запроса/недостоверного сообщения**, а не обещание, что каждый удалённый сервер отвечает на HTTPS-проверку.

### GeoData: достоверное расписание и read-only doctor (PR #1176)

Штатное расписание обновления GeoData теперь синхронизируется с настройками FreeNet и умеет показывать фактическую дату последнего запуска и диагностическое состояние. Сохранение настроек выполняется со строгой проверкой результата. Изменение устраняет ситуацию, когда включённый интервал существовал в интерфейсе, но отображаемая следующая дата оставалась в прошлом.

### Наследуется из предыдущих Beta

- Beta10 (PR #1174): общий mutation lock между `xkeen -ug` и Xray watchdog / VPN apply; подтверждение post-update состояния Xray, безопасный STOP вместо ложного успешного результата.
- Beta9 (PR #1170): обработка PID lifecycle (живой/zombie/reused/UNKNOWN/D-state) при core-only переключении VPN с сохранением fail-closed и rollback.

## Ограничения и установка

**Это Beta prerelease, не Stable.** На переносном Giga аппаратная приёмка этой версии ещё не выполнялась: после обновления отдельно необходимы read-only status/doctor, одна явно контролируемая ручная смена VPN с checkpoint и подтверждением восстановления/rollback, затем проверка AUTO и GeoData по журналу. Без таких фактов нельзя объявлять старую проблему перехода Вена → Берлин устранённой только по CI.

FreeNet не переустанавливает существующий XKeen/Xray, не должен перезаписывать subscription credentials, DNS и routing policy в ходе штатного self-update. Перед установкой обязательно подтвердить точный Beta tag, SHA256SUMS, plan, backup, отсутствие PENDING/UNKNOWN checkpoint и возможность отката. При FAILED/UNKNOWN — STOP, без автоматических повторных mutation.
