# FreeNet Router v0.8.0-beta.36

## Что изменилось

### Надёжное обновление Xray без обхода проверки и без потери рабочего VPN

- **Официальные каталог и архив Xray скачиваются через DIRECT**: FreeNet создаёт отдельный HTTP-клиент без системных HTTP(S)-прокси, помечая исходящие сокеты `SO_MARK=255` — так же, как собственные изолированные Xray-пробники. Если безопасный прямой сокет создать нельзя, обновление остановится; скрытого переключения на VPN нет.
- При обновлении Xray сохраняется обязательная семантическая проверка **установленного и нового бинарника** на фактической живой конфигурации до замены. Исходные 35 секунд сохраняются. Если проверяющий процесс всё ещё реально расходует CPU в последних 5 секундах перед дедлайном, FreeNet даёт **этому же процессу** дополнительное ограниченное время (не более 95 секунд от запуска). Если активности нет, истекает общий лимит или `run -test` завершается с ошибкой, срабатывает STOP **до замены** бинарника.
- Оба семантических теста по-прежнему должны завершиться с кодом 0. Увеличение окна наблюдения **не является обходом проверки**, а CPU-активность не приравнивается к результату PASS. Сохранены exclusive fence, snapshot, контролируемый restart, post-apply acceptance и rollback.
- Ошибки дополнены раздельными безопасными кодами: остановка из-за отсутствия CPU-прогресса либо по предельному времени при продолжающейся работе. Browser UI согласует результат с квитанцией detached-worker и не объявляет terminal FAIL, если операция ещё RUNNING.
- В Xray → «Обновить» добавлена **отдельная авторизованная диагностика установленного Xray** с безопасными временными/CPU-показателями и кодом выхода. Она запускается вручную и не меняет версию или конфигурацию. Не передаются stdout/stderr, секреты, PID и приватные пути.

### Что устранено и что нельзя обещать без аппаратного PASS

- Ранее на Portable FreeNet beta.35 попытка перехода Xray v26.9.9 → v26.10.21 завершилась `reason=xray-live-test-timeout` на проверке **действующего ядра**, уже после получения нового архива, без замены. Теперь FreeNet отделяет длительную реальную обработку от зависания и может завершить валидную длительную проверку. Окончательный результат конкретного Portable устанавливается только штатной аппаратной приёмкой, не CI.
- Если проверка по-прежнему не подтверждается, FreeNet сохраняет установленный Xray v26.9.9 и прекращает mutation. Ни новая версия, ни срок проверки не считаются автоматически безопасными.
- Клиентские HTTPS body stalls (#1225), переключение Extra (#1227), DNS/routing и действующая подписка в этой задаче не изменялись. Main/stable не затрагиваются.

## Проверки и приёмка

- CI: Go/transaction/browser тесты, исходный 35-секундный soft gate, остановка idle, продолжение при доказанном CPU-прогрессе, hard STOP без PASS, нераскрытие секретов, неизменность бинарника при диагностике, HTTPS DIRECT без HTTP(S)-proxy.
- При реальном применении на Portable: сначала **штатное обновление FreeNet до beta.36** с подтверждённой квитанцией; затем одна управляемая операция Xray v26.10.21 через Control Center, только при PASS preflight установленного и нового бинарника, snapshot и rollback. После неё отдельно подтвердить версию Xray, здоровье VPN и отсутствие неожиданного изменения endpoint.
- При `ROLLBACK FAILED/UNKNOWN` — STOP, без повторных попыток. Другие роутеры не обновляются в этом цикле.
