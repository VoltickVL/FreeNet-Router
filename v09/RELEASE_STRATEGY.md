## 1. Что мы делаем

**FreeNet 0.9 — совершенно новое самостоятельное приложение**, Control Center/PWA для Keenetic/Netcraze с Entware. Оно обнаруживает штатную установку XKeen/Xray и предоставляет через браузер удобное и безопасное управление **их оригинальными функциями**.

- **Xray-core:** единственное ядро VPN, DNS и маршрутизации (VLESS/Reality, outbound, balancer, routing, DNS).
- **XKeen:** единственный интегратор Xray с роутером, сетевыми хуками, GeoData, службами и штатными обновлениями.
- **FreeNet 0.9:** веб-интерфейс, добавление/обновление собственной подписки, тонкий адаптер к нативным конфигурациям и командам, диагностика и проверка результата. Без второго сетевого движка.

**Название:** FreeNet Router — проект; FreeNet Control Center 0.9.0 — новая реализация. Менять название не нужно.

## 2. Три НЕЗАВИСИМЫЕ линии версий

| Компонент | HOME до испытаний | Цель |
| --- | --- | --- |
| FreeNet | 0.8 — работающая **старая панель** | Новый FreeNet **0.9.0 с нуля**. Не upgrade/migration её backend |
| XKeen | 2.1 Stable — **оригинальная сторонняя система** | Оригинальный **XKeen 2.2 Beta**, отдельное штатное обновление |
| Xray | 26.10.31 — работающий оригинальный core | **Оставить установленную версию**, если она исправна и совместима |

**Нельзя говорить «обновить FreeNet 0.8 до XKeen 2.2» — это разные продукты.** Обновление XKeen и чистая установка FreeNet — разные операции, с отдельной проверкой и без одновременного изменения сети и UI.

Цель XKeen 2.2 Beta подтверждена upstream tag `2.2_Beta` (`bc9b59bdf46495d486f706bac05a7adf5db6b958`); перед применением сверить доступный официальный релиз/архив с точным upstream и совместимость с текущим HOME.

## 3. Что сохранить и что не наследовать

**Сохранить как пользовательскую ценность:** приватную VPN-подписку и доступы, работоспособные серверы, нужные DIRECT/VPN/BLOCK правила, пользовательские доменные списки, политику интернет-провайдера и рабочие штатные параметры XKeen/Xray. Не публиковать URL, UUID, Reality keys, токены и полные конфиги.

**Не наследовать FreeNet 0.8:** исходный код, собственную реализацию Split DNS/DNS proxy, AutoVPN/Live Pool, собственный firewall writer, cron/GeoData scheduler, legacy UI state, внутренние профили/службы, «миграционные» скрипты и исторические исправления как программную архитектуру.

**Ключевая разница:** «новая установка» относится к приложению FreeNet, **НЕ** к сбросу роутера и не к удалению пользовательских VPN-правил/подписки. Данные берутся из фактического нативного состояния/разрешённого пользовательского ввода, не из API/механизмов 0.8.

### Особое правило DNS

**FreeNet не поднимает собственный DNS-сервер и не реализует Split DNS.** DNS и доменное разрешение остаются в оригинальных Keenetic/XKeen/Xray механизмах — ровно один подтверждённый владелец нужного DNS-пути.

На HOME старый FreeNet 0.8 вписал техническую Split DNS-схему в штатные Xray `02_dns.json`, `03_inbounds.json`, `04_outbounds.json` и `05_routing.json`. В текущем HOME выявлены `dns-direct`, `dns-vless`, `dns-out`, `proxy_dns=off`. **Следовательно, нельзя ни слепо копировать текущие JSON в «чистую» 0.9, ни удалять их вслепую.** Сначала read-only анализ зависимостей и фактического DNS owner, затем формирование минимального native Xray candidate с сохранением пользовательских DIRECT/VPN правил, штатный `xray run -test -confdir`, отдельный контролируемый apply/acceptance и возможность возврата. Если provenance неизвестен — STOP, без автопочинки.

## 4. Реальная установка на существующий HOME

1. **Read-only preflight:** обнаружить XKeen, Xray, оригинальные правила, существующую подписку, состояние 0.8, владельца DNS/маршрутов, конфликтующие службы; определить конкретный expected delta. Если partial/unknown — STOP.
2. **Отдельное обновление оригинального XKeen 2.1 → 2.2 Beta:** только штатным upstream-механизмом, при проверенной целостности архива, доступности восстановления, проверке Xray и результатах работы сети. Не переустанавливать Xray, не трогать FreeNet 0.8 в этой же транзакции. При неизвестной возможности отката — STOP.
3. **Чистая установка FreeNet 0.9:** свой бинарник, конфигурация и init в независимом `/opt/freenet-v09`/префиксе 0.9. Автообнаружение состояния и **Browser Setup**; HTTPS и администратор, без ручных SSH-ритуалов при обычной установке. Не импортировать 0.8 backend/cron/конфиги приложения.
4. **Native policy/adoption:** показать обнаруженные пользовательские маршруты и подписку; убрать только подтверждённые технические зависимости 0.8 из предложенного **кандидата** штатного Xray (не из live автоматически); проверить DNS, DIRECT/VPN, серверы, подписку и нативные XKeen-функции. Секреты остаются приватными.
5. **Один активный контроллер:** 0.8 остаётся работоспособной до подтверждения нового браузерного доступа и безопасного контролируемого включения 0.9. Не запускать одновременно два writer для VPN/DNS/routing. Затем отдельно отключить legacy 0.8 и её **собственные** jobs, не трогая оригинальные XKeen/Xray, пользовательские конфиги и подписку. Не удалять оригинальные данные только из-за их расположения в ранее используемой 0.8 папке.
6. **HOME acceptance:** проверить настоящие клиентские DNS, HTTPS, VPN egress, DIRECT/VPN/YouTube и работу после перезагрузки. Доказать успешность, а не только `xray -test`/наличие процесса. Неутверждённые сервисные правила (например Bosch) не придумывать.
7. **Один релиз:** terminal CI success, cross-build arm64/MIPS/MIPSLE, SHA256, точный source SHA, GitHub `v0.9.0`, README/инструкция установки из браузера. Только после действительной HOME-приёмки объявить полноценный релиз.

**Первый canary — HOME сейчас.** Затем PORTABLE, после него WORK. MOM и другие действующие роутеры не менять без отдельного безопасного цикла. Предыдущий PORTABLE-first план отменён.

## 5. P0 release-only: что необходимо успеть

| Порядок | P0 gate | Подтверждение |
| --- | --- | --- |
| 1 | Native DNS/routing/subscription provenance, без наследования Split DNS | Plan с точной дельтой; candidate Xray validation; секреты не покидают устройство |
| 2 | XKeen 2.2 Beta HOME с сохранением рабочего Xray и пользовательских правил | Подтверждённая версия, init/process, работоспособность VPN/DNS; известный recovery |
| 3 | Независимая 0.9 + bootstrap/Browser Setup + HTTPS auth | Вход из браузера, одна управляющая служба, не зависимая от 0.8 |
| 4 | Подписка, выбор штатных серверов/балансировщика, ISP/DNS/routing, native service controls | Понятное управление без FreeNet-own DNS/VPN engine; сохранение пользовательской policy |
| 5 | HOME runtime acceptance, затем CI/release | Клиентский DNS/HTTPS/VPN/DIRECT/YouTube и reboot; terminal SUCCESS, SHA и assets |

**Срок Management: срочный выпуск в оставшееся окно ~3,5 часа 07.11.2026.** Это приоритет исполнения, **не отмена safety gates** и не основание выдавать staged/CI-кандидат за установленный релиз. Всё не относящееся к этому списку откладывается.

## 6. Запреты и правило STOP

**НЕ добавлять в 0.9:** собственный Split DNS, DNS proxy, AutoVPN, Live Pool, новый balancing engine, GeoData cron, вторую систему маршрутизации, Raw Shell Terminal, Backup/Recovery Center, миграцию FreeNet 0.8, необязательный refactor/редизайн или новые фичи «заодно».

**Перед любой mutation:** назвать источник штатного механизма, baseline и expected delta; проверить кандидат и обратимость; сделать только эту транзакцию; проверить фактическое состояние и клиентский результат. `ROLLBACK FAILED`/`UNKNOWN` = STOP, никаких последующих изменений. Никаких secrets в GitHub/issue/PR/log. При неизвестных runtime-фактах сначала штатный bootstrap/doctor/UI, и лишь если нельзя — минимальный read-only SSH. Не создавать обязательный SSH preflight для обычного пользователя.

**Перед каждым PR:** перечитать именно этот документ, проверить main/open PR и активную задачу; одна техническая задача = один PR, только целевой scope, tests, terminal CI, base/head/diff и merge. После завершённого цикла обновить #7, затем #5 если изменилась стадия, закрыть временную issue. Никаких «поправим стратегию по ходу» без прямого продуктового решения Management.

## 7. Текущий подтверждённый статус (07.11.2026)

- Ветка 0.9: `experiment/v0.9-clean` содержит отдельную кодовую базу/предпросмотр, native API и тестовый stage. **Публичного v0.9.0 нет.**
- HOME: работающая FreeNet 0.8, XKeen 2.1 Stable, Xray 26.10.31, конфигурация штатного Xray проходит `run -test`; это **не** доказывает маршрут клиентского трафика. На HOME **не** установлены XKeen 2.2 Beta или FreeNet 0.9.
- Проверенный архив 2.2 Beta и штатный локальный backup XKeen 2.1 — не доказанная готовность к откату всей сетевой конфигурации. Обнаружен отсутствующий `/opt/etc/xkeen/xkeen.json`; updater запускать только после разрешения этого runtime-факта, не создавать файл по догадке.
- Следующая работа: **не новое обсуждение архитектуры**, а закрытие P0 gate по порядку выше.
