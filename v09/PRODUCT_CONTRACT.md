**Единственная утверждённая стратегия и порядок выпуска: [RELEASE_STRATEGY.md](RELEASE_STRATEGY.md). При расхождении текста и стратегии приоритет за ней.**

**Решение Management от 07.11.2026.** Это главный критерий для каждой задачи 0.9: **не строить комбайн**. Реализовать **один законченный `v0.9.0`**, а не устанавливать пользователю набор сырых промежуточных версий. Разработка изолирована в `v09/`, целевая ветка — `experiment/v0.9-clean`. Источник истины: Roadmap #5 и Journal #7.

## Обязательный upstream-ориентир и стенд — решение Management 07.11.2026

- **Целевой upstream для FreeNet 0.9: XKeen 2.2 Beta, а НЕ XKeen 2.1 Stable.** Исторические тесты, CLI-аргументы и совместимость с 2.1 не считаются подтверждением работы на 2.2 Beta.
- Перед любым новым native PR/вызовом проверять **точный доступный upstream 2.2 Beta tag/commit и его реальный код**, включая CLI, init, updater, GeoData, speed balancer и форматы конфигурации. Если конкретный механизм 2.2 Beta не подтверждён — **STOP**, не переносить предположения из 2.1.
- **Решение Management от 07.11.2026: первый испытательный роутер — HOME сегодня**, поскольку PORTABLE физически в офисе. После подтверждённой домашней приёмки — PORTABLE, затем WORK. HOME = разрешение готовить и испытывать безопасно, **не** разрешение вслепую переключать рабочий сетевой стек. На HOME read-only установлен XKeen 2.1 Stable, Xray 26.10.31, FreeNet 0.8; приоритет — STAGING_ONLY до доказанной совместимости native policy и раздельного отключения 0.8. Штатное обновление XKeen 2.1→2.2 Beta разрешено Management **только отдельным проверяемым циклом** после подтверждения обратимости; partial/unknown = STOP.
- Фиксация ориентира **не означает**, что XKeen 2.2 Beta уже установлен или что функции/обновления прошли проверку. До завершения Browser Setup, штатных controls, runtime canary и чистой замены 0.8 публичный `v0.9.0` не выпускается.

## 1. Единственная цель

**FreeNet 0.9 = красивая браузерная/PWA-оболочка и минимальные адаптеры управления ОРИГИНАЛЬНЫМИ XKeen и Xray-core на Keenetic/Netcraze с Entware.** Она позволяет:

1. **Добавить и обновить свою VPN-подписку** (сохранить URL/credentials приватно, получить серверы, представить их штатными Xray outbounds, проверить и применить).
2. **Управлять штатными функциями:** серверы, выбор ноды/балансировщик, DIRECT/VPN/BLOCK, DNS, ISP-профили, XKeen/Xray service start/stop/restart и поддерживаемые действия XKeen.
3. **Видеть реальное состояние и проверять результат:** версии, конфигурация, штатная Xray `run -test`, состояние служб и фактический клиентский VPN/DNS/HTTPS route. Наличие файла/процесса не равно работающему VPN.
4. **Обновлять FreeNet, XKeen, Xray и GeoData** штатными средствами upstream; отображать версию, доступность обновления, результат и ошибки.
5. **Использовать удобный интерфейс** на компьютере и iPhone (Safari Home Screen PWA), с безопасной аутентификацией и нормальным мобильным видом.

**Чего в продукте НЕТ:** пользовательского раздела «Резервные копии» или «Восстановление», отдельной системы backup/restore, архивов для пользователя, собственного AutoVPN, Live Pool, Split DNS engine, DNS-прокси, cron GeoData, второго balancer/router/firewall writer и raw-shell терминала. Не включать эти задачи в release gates, UI или дальнейшие PR без нового решения Management.

Техническая осторожность **не равна новой подсистеме бэкапов**: до изменения проверить native config, валидировать кандидата штатным Xray, минимально и атомарно применить только необходимое, проверить результат и STOP при неизвестном состоянии. Не удалять работающие данные и приложения до подтверждения замены. Если штатный updater предоставляет встроенный откат, можно использовать его, но **не разрабатывать собственный Backup Center**.

## 2. Чёткое разделение ответственности

| Возможность | Чей механизм | Роль FreeNet |
| --- | --- | --- |
| VLESS / Reality, proxy и серверы | **Xray-core** | Подписка и управление штатным outbound-конфигом |
| VPN balancer/Observatory, routing, DIRECT/VPN/BLOCK | **Xray-core**, при необходимости **XKeen `-sb`** | Показать/выбрать один штатный режим, без AutoVPN FreeNet |
| DNS и доменные правила | **Xray DNS + XKeen** | Показать и изменить native DNS/routing, без собственного Split DNS |
| TProxy, netfilter, ipset, жизненный цикл Xray | **XKeen** | Поддерживаемые команды/API через браузер; никакого второго writer |
| GeoSite, GeoIP, GeoIPSET, cron | **XKeen** или native Xray geodata (один выбранный владелец) | Показать статус и настройку штатного обновления |
| Обновление XKeen/Xray | **Штатный updater XKeen** | Доступный upstream канал/версия, безопасный вызов, результат |
| Обновление FreeNet | **Минимальный собственный updater оболочки** | Проверенный официальный release, без подмены XKeen/Xray |
| Подписка | **Нативная конфигурация Xray/XKeen** | Безопасно принять subscription URL; если upstream не имеет подходящего importer, сделать только тонкий преобразователь подписки в **стандартные Xray outbounds**, без собственной логики VPN |

Прежде чем писать новый код, исполнитель **сначала сверяет исходники и возможности точных версий XKeen/Xray**. Не предполагать наличие поддержки формата или CLI, которого upstream не предоставляет.

## 3. Экранная модель (никаких фиктивных кнопок)

- **Обзор:** версии и подтверждённое состояние, ISP, native VPN/DNS.
- **VPN / Подписка:** добавить/обновить приватную ссылку, показать ноды, выбрать native balancer/сервер, безопасно применить.
- **Маршрутизация / DNS:** ISP-пресеты и редактор штатных правил/списков XKeen/Xray.
- **XKeen / Xray:** состояние служб, native commands, конфигурационная проверка, журналы без секретов.
- **Обновления / GeoData:** проверка и штатные обновления, native cron.
- **Диагностика:** факты, ошибки, Xray config validation и подтверждённый путь клиента.
- **iPhone PWA:** узнаваемая иконка, standalone, responsive safe areas.

**Нет экранов «Backup», «Restore», «Recovery» и отдельного набора инструментов эксплуатации.** Пока управление ещё не написано, показывать «НЕ ГОТОВО», а не имитировать работу.

## 4. Чистая установка 0.9 без наследования DNS/автоматизации 0.8

**Последовательность и acceptance — только [RELEASE_STRATEGY.md](RELEASE_STRATEGY.md), разделы 3–6.** Этот раздел уточняет существующий контракт, но не вводит самостоятельную дорожную карту.

**СТРОГО:** 0.9 — новый продукт с нуля, а не миграция 0.8. Технические компоненты FreeNet 0.8 (свой Split DNS/DNS proxying, AutoVPN, cron, overlay rules и пользовательские настройки его UI) **не переносить и не воспроизводить**. Управление только нативными DNS/routing Xray и механизмами XKeen 2.2 Beta. Существующая VPN-подписка и пользовательская политика DIRECT/VPN должны быть сохранены по смыслу и после валидации, не через копирование legacy backend.

**Важное подтверждение HOME 07.11.2026:** прошлый FreeNet 0.8 встраивал Split DNS в штатные `02_dns.json`, `04_outbounds.json`, `05_routing.json` и DNS inbounds. На HOME read-only обнаружены маркеры `dns-direct`, `dns-vless`, `dns-out`; `proxy_dns=off`. **Наличие стандартного Xray JSON не делает его готовым для новой 0.9.** Эти файлы на первом шаге не изменять, а изучить зависимости и отделить пользовательские маршруты/подписку от старой DNS-схемы. Никаких догадок, автоматической очистки или подмены текущего DNS. Новая read-only карточка и `GET /api/native/preserved-sources` обозначают `NATIVE_CONFIG_REVIEW_REQUIRED`, а не `READY` или утверждённый перенос. `xkeen.json` на HOME отсутствует: не создавать его предположительно.

**Обновление оригинального XKeen 2.1→2.2 Beta** — отдельная штатная операция, не обновление FreeNet 0.8. Отдельная установка новой FreeNet 0.9 в `/opt/freenet-v09` выполняется с нуля, без импорта legacy settings. До её приёмки 0.8 остаётся рабочим; затем отключить только 0.8 writer/службу, сохранив текущие пользовательские правила и подписку. Без двух активных контроллеров.


**Новый Entware:** один bootstrap → Browser Setup → распознать installed/missing/unknown → установить только отсутствующий штатный XKeen/Xray → FreeNet 0.9 → добавить подписку, настроить ISP/DNS/routing → проверка.

**Существующий Entware + XKeen/Xray:** кроме **одного отдельно подтверждённого обновления оригинального XKeen 2.1→2.2 Beta на HOME**, не переустанавливать рабочее ядро, не трогать XKeen UI, subscriptions/credentials, списки, `/opt/etc/xkeen/`, `/opt/etc/xray/configs/`, GeoData. Временно разместить новый **FreeNet** рядом с 0.8 **только на период проверки**: старая служба остаётся единственной активной, пока новая не готова. После проверки браузерного доступа и native runtime корректно выключить только 0.8 и её managed jobs, включить **одну** 0.9. После приёмки удалить legacy FreeNet 0.8. **Не строить параллельные системы бэкапа/архивирования/восстановления.** Если безопасное переключение не доказано — STOP, старую 0.8 не удалять.

Промежуточный stage **не означает** готовую 0.9 и не включает управление, пока нет авторизации. По последнему решению Management первый аппаратный canary — HOME, затем PORTABLE и WORK; MOM frozen. Один стабильный `v0.9.0` выпускается после проверки, а не для проведения первых экспериментов на HOME.

## 5. ISP → native routing

- Владлинк и АльянсТелеком: YouTube → DIRECT.
- Ростелеком: YouTube → VPN.
- Подряд: самостоятельный ISP профиль, не копировать поведение другого провайдера.
- Custom: ручная экспертная политика.
- При обязательном VPN не создавать скрытый fallback в DIRECT.
- Вся маршрутизация исполняется Xray/XKeen, FreeNet лишь задаёт штатные правила.
